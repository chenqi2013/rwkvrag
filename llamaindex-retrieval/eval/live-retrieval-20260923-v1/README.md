# 2026-09-23 实时检索质量诊断 V1

目的：测当前本机 `18440` + SearXNG 的真实检索质量，尤其是多项目比较。该轮不更改模型、索引、提示词或服务设置，也不使用旧题训练答案。题目在运行前固定于 `cases.json`；3 道单项目题、8 道两至四项目比较题。

执行：每题调用一次 `/v1/search` 的 `web` 模式，`top_k=20`，保存完整响应、耗时和失败。对所有比较题另外调用一次本机 SearXNG JSON 接口，保留前 10 条，以区分搜索引擎排序与适配器截断。选 `compare_inference_3`、`compare_rag_3`、`compare_storage_3` 和 `single_repo` 各调用一次 `hybrid`；另对 `compare_inference_3` 与 `single_repo` 调用一次 `auto`。串行运行，避免并发出口负担。记录实际 Git 提交、设置文件 SHA-256、索引名、服务 URL、UTC 时间与 HTTP 状态。

评阅维度：实际返回数；题目中每个项目是否有*独立*官方项目资料（项目官方仓库/官方文档，标题提及项目不算自动合格）；有多少条只含搜索摘要；来源是否覆盖用户问到的维度；混合模式前 10 条中来源分布与主题相关性；`auto` 是否选中联网。多个项目出现在同一篇二手比较文章中不能算各项目官方证据。人工审读由实现者完成，非盲审；本轮没有语义答案准确率 Gold，不把诊断比例当作正式准确率。

运行前预期：每次网络查询目前 `web_search_results=2`，因此 `/v1/search` 的单轮 web 最多 2 条，三项目题不可能每个项目都有一条独立官方网络来源。引擎原始前 10 条若更丰富，说明入口截断是可见瓶颈，但不能单凭增加数量宣称最终回答变好。
