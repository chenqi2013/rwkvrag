# bm250820 原生 RWKV RAG：后续开发实验

这些记录接续[首轮实验](../bm250820-rebuild-20260908/README.md)。本轮将规划、原文选择、候选调度和回答引用分别检查，再运行完整 Wiki 链路。局部格式和事实回答有所改善，仍未建立可用于生产的问答质量保证。HTTP 成功、`completed` 或合法 E 编号均不代表答案正确。

所有问题都是已公开的开发题。Wiki 链路每轮固定 8 题、29 个必要事实；固定材料 Writer 每轮是另一组 8 题、28 个必要事实，含公开 Wiki 片段和明确标注的合成说明书。这两组分母不能混用，也不能当作新封存测试或自然用户随机样本。题目、原金标、完整输入、全部失败、模型原始输出及逐项 Codex 审阅都保留；审阅不是人工盲测。

## 完整 Wiki 链路

固定使用 RWKV 原生接口和同一 OpenSearch BM25 索引：5,000 篇真实 FineWiki 中文文章、45,960 个逐字来源块。索引 UUID 为 `AaG0YmAZT5i8EHEhJHyNYw`；本轮没有重新入库或改写索引，也没有每文档两块配额。每个检索问题最多取 80 个候选，融合后的总阅读来源预算与候选数量是两个不同参数。

v3–v6 的 Planner 与 Resolver 使用闭合 prefill `<think></think`，输出预算各 1,024；Writer 保留开放 prefill `<think` 和 2,048 输出预算。完整原始历史仍传给下游；Resolver 输出 E 单元选择，代码只接受通过编号、原文身份和范围校验的选择；代码不能补造字段覆盖、改写答案或添加引用。题目并发为 4，原生调用并发上限为 32，观察到的实际峰值也是 32。

## 分阶段诊断

- **Resolver 闭合 prefill，192 次重放。** 只改 prefill，沿用原严格字段解析器，合法数从 127/192 降到 119/192。仍只有三个选中单元；六个字段—单元绑定中五个支持所求信息，一个不支持。固定完整金标原文覆盖由 2/29 到 5/29，但没有调用 Writer，不能据此宣称问答提升。另以新语法解析旧输出只是离线诊断：147/192 与 153/192，不回写旧分数。
- **task_units，192 次重放。** 合法选择为 185/192，选出 22 个单元；逐个核原文后，仅 8 个支持当前所求的至少一项具体信息，14 个不支持。相对闭合字段方案新增的 19 个单元中仅 5 个有这种支持。完整金标原文覆盖为 10/29；这里不评逐字段覆盖，也没有最终答案分数。
- **Planner 同源任务表。** 第一轮要求 `{"queries":[完整子问题]}`，模型八次均返回顶层数组，固定解析器全部拒绝，可用计划 0/8。第二轮明确要求字符串数组，格式 8/8，通过完整主体、撤回和目标范围检查的只有 6/8；Ghost 主体遗漏与撤回船名恢复仍保留失败。没有包装输出、补主体或再问一次救分。
- **复用既有 queries。** 只读审阅中，旧 query 集合作为独立完整任务标签是 5/8；结合原完整历史，活动目标集合相容为 8/8。这两个口径不同，均不是问答准确率。v4 固定对全部题采用同一数据流，而不是按题挑 fields 或 queries。
- **候选调度。** 在已公开 29 个事实的完整原文覆盖诊断中，24 来源预算下 RRF 为 20/29，query 轮流取项为 24/29；80 来源时分别为 26/29、29/29。原候选身份和 RRF 分数保留，没有按文档限额。此处只是指定 AND/OR 原文跨度的覆盖，替代证据和实际回答仍须另审；不能把 29/29 覆盖写成 29/29 答对。

## 两个 Writer 候选均不采用

两批均重放 `materials-smoke-v2` 的实际完整 Writer 输入，保留原资料顺序、裸资料标签、历史、问题、模型与采样参数、2,048 输出预算。每批 8 次生成、16 次原生 HTTP、峰值并发 8，没有重试或改答案。

闭合 Writer 没有改善完整通过率，并出现工作站问题只复述请求、三项事实全漏等退化，故不采用。末尾提醒使两个题目补上正式且正确的引用，但仍把 305 系动力车数 4 写成 2、把已提供的 Daytona 误称未提及，并把事件模型错引到另一标准的资料。

末尾提醒的晋级条件在调用前已登记：8 个自然完成、事实正确至少 27/28、错误不多于 1、正式完整大于 1/8、人读完整大于 2/8，且逐项语义与额外引用检查照旧。实测只有 26 项事实正确，未达门槛。`materials-writer-citation-suffix/PROMOTION-DECISION.json` 保留不采用决定；没有将该提醒或闭合 Writer 自动写入生产配置。

## 记录范围与复算

新归档包含两组 Resolver、两组 Planner、两组 Writer 和 Wiki v3–v6 的原始调用，以及冻结源码、启动与传输记录、控制差异、逐项审阅和相关测试日志。按独立新生成计，共 1,697 次生成、3,394 次原生 HTTP；归档中的旧 baseline 副本不重复计数。只读诊断、CPU 预检和未运行的准备失败也单独保留，不能算成模型请求。

原 `source-wiki-v4-preparation-incomplete` 和更正记录保留，准备异常没有调用模型。所有模型长度失败、解析失败和质量失败均按原分母保留。原始记录不重写；`.env`、依赖目录、缓存、重复传输压缩包和可变进度标记不进入归档，排除项记入清单。秘密值检查覆盖常见密钥模式、结构化认证字段和 base64 HTTP 数据，检查发现问题会停止并且不打印值；这不是对所有可能敏感内容的无限保证。

归档清单为 [RECORDS-MANIFEST.json](archives/RECORDS-MANIFEST.json)，选择清单为 [ARCHIVE-SELECTION.json](ARCHIVE-SELECTION.json)。每个压缩包必须小于 50,000,000 字节，清单同时记录压缩包及每个原文件的大小和 SHA-256。本次六个压缩包共 **42,717,215 字节**，包含 **7,311 个原文件、251,526,849 字节原内容**；最大 `wiki.tar.gz` 为 **29,526,614 字节**。清单 SHA-256 为 `15d8c87f2f3773bf68501207e2bcc075ec9d32d429df099e5ad5554dffd2df56`。

可分别下载 [checks](archives/checks.tar.gz)、[diagnostics](archives/diagnostics.tar.gz)、[planners](archives/planners.tar.gz)、[readers](archives/readers.tar.gz)、[wiki](archives/wiki.tar.gz)、[writers](archives/writers.tar.gz) 六包，并保留同目录清单。完整逐成员检查和实际解包均已通过，原首包六个文件的 SHA 也复核不变。

在本目录运行（Python 3.11+；只核字节，不调用检索或模型）：

```sh
python3 build_archive.py verify \
  --manifest archives/RECORDS-MANIFEST.json \
  --extract /tmp/rwkvrag-followup-records
```

`--extract` 必须指向尚不存在的新目录。校验先核所有包和成员，再解包；路径穿越、额外或缺失成员、重复路径、符号链接、大小或哈希不一致均拒绝。解包后保留 `records/` 下的原相对路径。

从已有完整记录重新准备另一个归档：

```sh
python3 build_archive.py prepare \
  --records /path/to/rwkvrag-bm-rebuild-20260908 \
  --selection /tmp/followup-selection.json
python3 build_archive.py build \
  --records /path/to/rwkvrag-bm-rebuild-20260908 \
  --selection /tmp/followup-selection.json \
  --output /tmp/followup-archives
```

选择文件和输出目录也必须是新的。wrapper 复用相邻首包目录中的 `build_archive.py`，因此要保留仓库中两个实验目录。校验成功只说明记录字节完整；已有语义审阅的理由须阅读逐条记录，不能由 SHA 或解析器自动证明。若要执行记录里的阶段审计或审阅序列化脚本，还需按其固定绑定提供首包中的 v2 原记录；它们可能引用旧来源或旧审阅，而且通常拒绝覆盖已有输出。源码清单中的原服务器绝对路径只记录当时环境，不意味着另一台机器可仅凭路径重新运行模型。
