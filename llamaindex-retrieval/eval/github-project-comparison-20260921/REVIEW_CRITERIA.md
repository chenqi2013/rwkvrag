# 主验收审读口径（回答生成前登记）

1. 分开记录请求的项目、搜到的项目、Reader选中证据覆盖的项目、答案实际比较的项目。提到名字不等于覆盖了能力与取舍。
2. 完整比较应围绕用户目标跨项目说明相对优势、代价及适用条件；逐个写介绍不能当完成选型。不是强制给每个项目排名；缺关键证据时允许有依据的未决结论，但不能假装全部比较过。
3. 对“X比Y更好”“Y不支持”等比较断言检查两侧实际证据、版本与范围。功能支持、需额外配置、依赖外部模型、未查到说明必须区分。README宣传不能当质量实测。
4. 推荐必须保留当前有效的离线、硬件、维护与引用要求。优先项不是硬门槛；未知不能当不支持。多轮中不能沿用已撤回的Wiki优先级。
5. 引用语法与语义分别判断：可点击不等于来源支持，某一项目文档不能自动证明另一项目没有某功能。
6. 复读、预算失败、规划失败、检索失败、证据误选分别记录；没有最终答案不能计为谨慎拒答。
7. 每题给出通过/部分/失败及具体依据，不以字数、网页数、接口200或出现关键词代替审读。实现者非独立复核，8次问答不是商业可靠性估计。
