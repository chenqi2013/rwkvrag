# RWKV 模型导航与逐信息项回答

`pipeline: "needs"` 是默认关闭的试用候选。实现与接口说明如下；实现、单元测试通过和服务启动都不能证明最终回答正确。最终质量需要独立审读正确性、完整性、来源要求和逐字证据支持。

## 调用与证据

模型负责信息项、查询、导航、相关性判断和回答。代码负责分批、并发、按模型分数排序、去重、预算、ID绑定和结构校验。该路径不使用 BM25、关键词/词项评分、embedding 或向量检索，也没有实体或问法专用分支。

1. 上下文整理后的完整问题进入 PLAN，由模型列出信息项和分渠道查询。
2. KB 查询通过模型卡片锦标赛选文件，再下载逐字原文；Web 查询取得提供方的原文快照。
3. 阅读窗口默认3000字符、overlap240，内部采用640/80逐字片段。SCORE 按信息项给片段2或3分，其他片段不返回。
4. 每项采用模型分数最高的至多3个片段。3分片段多于3个时，另发 PICK 比较调用（至多8个候选、4000字符）。
5. ANSWER 逐项回答：`found` 必须引用本次提供的片段，`not_found` 必须不引用。结构错误保留 raw 并记为失败，不能改写成成功。
6. 未找到/失败的信息项驱动 REQUERY，最多2轮、补查300秒，只读新增原文并重答未解决项。
7. COMPOSE 只接收结构通过的 `found` 短回答及来源标识，未解决项只传名称；没有任何 `found` 时不调用 COMPOSE，返回 `no_evidence`。

`found` 与合法引用仅表示模型声明和结构通过，**没有证明语义支持**。混合结果的汇总仍可能出错，必须审读；代码不删句、不补引用、不替换模型回答。修复需要带独立 trace 的新模型调用。

可选的 `needs_options.answer_protocol: "quote_v1"` 在逐项输出中增加 `quote`：`found` 必须给出10–300字符且在恰好一个引用片段中逐字出现的引文；`not_found` 必须给出空引文和空引用。无效节点保留raw并继续视为未解决。默认合同仍为 `"current"`。

汇总方式由 `needs_options.final_mode` 选择，默认 `"compose"`。`"assemble"` 直接显示各个已找到项的模型答案原文及引用，并为未解决项各加一行 `未找到：<信息项>`，没有终答模型调用。`"checked_compose"` 输出带逐句引用的 `sentences` 数组，每句必须引用已找到项的片段；任何结构或ID错误使整份终答无效。显示投影和模型原始输出分别保存，不把格式通过当作事实核验。

试用客户端在 `needs` 配置下将完整输入加输出预留的 token 上限约束为6000（更小的显式配置仍有效），每次调用通过服务 `/tokenize` 检查。超出记为预算失败，输入与 raw 不截断。字符窗口只是分批工具，不能代替实测 token 计数。完整问题、超长原子表格或过多信息项都可能触发预算失败。

## 文件导航卡片

`kb_cards: {知识库ID: "/absolute/path/CARDS.jsonl"}` 指向离线生成的文档卡片。每行含 `id`（文件ID）、`title`、`summary`、`entities`、`category`。卡片基于标题和开头1200字符，与用户问题无关；生成失败的文件保留标题、失败 raw 和类别“其他”。

查询默认不作类别门控。每批最多25张卡片，使用本批短ID，由模型初选至多2份；对各批胜出者继续锦标赛，最终至多4个文件。类别门控 `use_categories` 默认关闭。

顶层 `kb_navigation_options: {"mode": "titles_then_cards"}` 可选择标题初选：每250个标题使用短ID选择至多5个，再对胜出卡片每25个选择至多2个，最后选择至多4个文件。5000标题最多20次标题、4次卡片和1次最终选择；目录大小和失败会影响实际调用数。`"titles_only"` 使用每100个标题至多3个胜出者的纯标题锦标赛。两种标题模式要求类别门关闭、最终文件数1–4；默认 `"cards"` 保持原卡片流程。调用预算由服务tokenizer检查，失败选择保留raw，不补造文件ID。

卡片必须对应当前目录版本。没有完整文件卡片的目录使用已有的模型标题选择，不把旧目录ID套到新目录。

卡片均是模型派生的导航线索，**不是事实证据**。只有下载到的逐字原文进入阅读。`acquisition` 保留每轮选择、原始输出、失败和最终文件ID；导航命中与调用成本不能替代最终答案验收。

## 审计边界

逐调用记录保存精确 prompt、raw/hash、输入证据ID、服务 tokenizer 预算、状态与耗时。结果 `telemetry` 汇总各阶段调用数、未完成数、输入token中位数和最大值；`max_generation_tokens` 与 `max_not_sent_tokens` 分别保留实际提交生成和生成前被阻止的输入大小，`max_tokens` 仍包含全部已计数输入。`need_answers`、`missing_need_ids`、`graph`、来源快照、引用片段坐标及 `citation_bindings` 可用于独立复核。

实验脚本、数据、卡片实件、评分与 State 文件在本地研究工作区管理，不随应用发布。State 路由是单独配置，不能根据存在 State 文件或上传成功推断质量提高。应用默认配置不因这些候选自动变更。
