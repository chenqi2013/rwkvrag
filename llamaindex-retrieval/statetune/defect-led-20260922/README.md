# 以已观察缺陷决定StateTune数据

状态：2026-09-22，已完成最近36题的节点失败盘点、标注任务合并及8份校正范例。**尚未生成大规模合格训练集，尚未训练，未修改模型或生产提示。** 用户已明确要求减少预设分类，先统计真实缺陷，再据此生成足量且广覆盖的数据。

## 只保留三个工作方向

| 方向 | 已有证据 | 由证据决定的数据内容 |
| --- | --- | --- |
| 取对事实并绑定出处 | 397次引文不逐字；226次范围不逐字，其中101次把标题当范围、11次把对象名当范围；另有抄对原文却答错字段/对象的已审读例子 | 根据真实错误生成新材料：标题与范围有区别；值、对象、属性及适用范围必须一致。加入应输出null和不应输出null的对照，不能一律清空范围或拒答 |
| 读对处理状态 | Writer将未检查任务272说成0、将失败当未记载、根据总数虚构逐来源过程 | 状态数值与对应含义绑定；区分输入存在、处理失败、未检查和最终无证据。更换状态组合时，目标解释随之改变，不背固定拒答 |
| 回答完成后结束 | 普通零值题从能结束变成重复触顶；同输入也有文字漂移 | 完整回答所问字段后结束，保留引用与缺失项。训练终止行为；运行路径导致的漂移另查，不承诺State能修复引擎数值问题 |

这是工作方向，不是互斥的根因分类。首个校验错误可能遮住对象或字段错误，不能按错误字符串机械生成正确标签。“官方训练数据脏”尚未由本轮证据验证。

- 36题、2391次旧模型调用，731条失败记录；726条能关联模型调用，5条为没有对应模型调用的执行记录。未新调用模型。
- 引文/范围两种校验失败共623条，占失败记录85.2%，不等于85.2%的问题答错，也不等于修掉它们就能恢复全部正确答案。

## 后续生成与分集规则

1. 每条新数据绑定具体缺陷证据、原始材料和目标理由。没有被观察或明确说明的能力缺口，不为凑分类新增大批样本。
2. 先扩充独立来源和任务结构，再增加必要变体。换名字、数字、措辞或顺序仍属于同一材料/模板族；不能被计成新的覆盖。
3. 所有同源文档、改写、成对反例、节点及完整轨迹组成一组；先按组划分训练/开发/留出，再生成。跨组近重复需排查，不能仅凭不同ID认定独立。
4. 本次旧36题和Writer144条都是已见诊断集，不进入“未见留出”。校正范例不自动进入训练导出；若后续明确纳入训练，它们永远只作为已见回归报告。
5. 完整轨迹从实际缺陷及任务需要产生：有的直接回答，有的先消解范围，有的恢复失败或继续取证。不给所有样本强套同一条长路径。
6. 原文位置、引用、数值与范围做程序核对；对象/字段/条件的语义对应做标注与复核。错误模型输出只作为反例保存，不能自动当gold。逐字匹配不替代语义复核。
7. 保留原本能回答的普通题和正例，防止把全部输出训练成null、拒答或固定解释。用实际答案完整度、错绑/错荐、引用、复读和延迟决定是否改善。
8. 数据量保持大规模目标，但不按“每类固定若干千条”配额填充。本轮先建立可审查的缺陷依据；扩展数量随独立来源、不同任务结构和复核通过数报告。2万～3万条与2千条轨迹只是此前规模估计，不是可用数据成果或必须凑满的门槛。

可复用`state_tokens.encode_training`的原始prompt边界、target-only loss及EOS编码，以及`state_training.read_training_tokens`的SHA、样本数和掩码检查。不能直接运行旧`statetune/train_state.py`：它是21样本/11步的冻结试验脚本，不能改历史契约来承载新训练。

## 复现盘点

在仓库根目录执行，输出目录/文件必须不存在：

```bash
rtk proxy python3 scripts/statetune_defects/audit.py --out data/statetune/defect-led-reproduction
rtk proxy llamaindex-retrieval/.venv/bin/python scripts/statetune_defects/prepare_examples.py --out data/statetune/defect-led-reproduction/DIAGNOSTIC-EXAMPLES.jsonl
rtk proxy llamaindex-retrieval/.venv/bin/python -m pytest -q scripts/statetune_defects/test_audit.py
```

旧输入SHA保存在归档的SOURCE-PINS.json；汇总不能覆盖既有原始回答。此脚本不会生成训练token或调用模型。
