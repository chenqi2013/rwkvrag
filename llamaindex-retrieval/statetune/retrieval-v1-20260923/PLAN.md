# 检索专用 StateTune V1：数据与验收登记

状态：**规划协议、来源快照和数据准入工具已实现，运行链路尚未接入；教师试点数据未达准入标准，没有新训练或质量收益**。[来源与试点记录](../../../docs/archive/2026-09/retrieval-state-data-prep-20260923.md)保存具体数量和失败。历史冻结题、旧训练发布集和正式服务不改。基线依据[当前状态](../../../docs/CURRENT.md)、[完整联网回归](../../../docs/archive/2026-09/live-retrieval-complete-20260923.md)、[多项目取证设计](../../../docs/RETRIEVAL_COVERAGE_DESIGN.md)及[新题 State 验收](../../../docs/archive/2026-09/state-fresh-github-paired-20260923.md)。

## 为什么不能直接续训旧发布集

已训练的 3940 条主要监督 Resolver 和 Writer；24 道新固定材料题中，12 道大型比较题在零 State 和训练 State 下均无完整正确答案。当前正式联网路径还会把对象×维度待查项当搜索式，超过 6 条回退原题，联网只执行前 2 条。这是**训练目标和执行协议的缺口**：单纯增加 Writer 样本或换学习率不能让未执行查询产生证据。原 65 道联网题、434 道恢复题和已见 State 题只作回归及错误分类，不作为本版本训练 prompt、目标或教师参考答案。

## 一次只训练一个检索决策

1. **规划 State（首轮）。** 输入完整有效对话；模型输出所需对象、维度、限制条件、`grid` 或显式组合，以及每对象一条自然搜索式；[实验协议](../../src/llamaindex_retrieval/retrieval_plan.py)机械生成完整待查格子，3×3 只需 3 条首轮搜索式但保留 9 格。待查格子可多于执行并发，不能因搜索预算删格。普通单对象问题仍只生成必要格子；多对象题覆盖 2–6 个对象及共同/非共同维度。协议目前没有接入运行链路；[编译器](../../../scripts/retrieval_statetune/prepare_plan.py)能生成逐字 batch 提示和只监督目标/EOS的 token 行，但这些行仍是草稿，须先通过独立审读和准入门槛。
2. **证据判断 State（第二轮独立实验）。** 对一个明确格子读取相同来源快照，判断对象、属性、版本、时间、条件是否一致；输出逐字跨度和 `supported`、`insufficient` 或同范围冲突的模型判断。来源尚未搜索、供应商失败、正文抓取失败由执行状态记录，不许训练成“资料未记载”。不从 snippet 伪造正文。此 State 与规划 State 分开从零训练。
3. **缺口补查 State（第三轮独立实验）。** 仅依据未解决格子、已尝试查询和来源，给出确有新信息价值的补查式或停止；重复查询、无新证据继续循环属于负例。只有规划与正文取证基线稳定后再做，避免混合变量。

Writer 的复读、引用语义与分层结论仍需单独实验；本版本不把它们混进“检索命中率”。路由错误、Tavily/SearXNG 故障、正文抓取、候选深度和搜索总预算是工程/供应商变量，不能归功或归咎于 StateTune。

## 数据来源与目标数量

先按**项目或文档来源族**分训练、开发、盲留出，再写题/调用教师；同一个仓库的 README、文档、不同版本及改写题只能落在同一分区。已见评测仓库、旧 434 题来源和旧发布集材料另列禁入清单。仅靠字符串去重不能证明语义隔离，最终需抽检仓库别名、镜像和转载。新题保留原始自然问法，不把 `site:` 或搜索引擎语法当成用户措辞。

第一批[120份来源快照](SOURCES.json)已采集且分区，但训练只有84族，低于表中规划角色所需120族；此批仅供试点与扩充设计。试点发现让教师同时写问题和完整标签会漏项目/维度；新版本先固定完整标签结构，再生成问题，不复用失败草稿充数。

[标签先行试点](../../../docs/archive/2026-09/retrieval-state-label-first-pilot-20260923.md)验证了这一生成顺序的结构收益（96份计划、95份逐字范围匹配问题），也暴露来源 topic 的可比性不足。试点均 `review.accepted=false`，新数据版本先审读项目角色与自然比较场景，再扩充来源并冻结新盲集；不能从95条直接启动训练。

| 决策 | 准入训练目标 | 最少来源族 | 覆盖重点 |
| --- | ---: | ---: | --- |
| 规划 | 2400 | 120 | 单对象、2–6 对象、3×3/4×4 比较、版本/日期/否定、历史撤回、非网路题 |
| 单格证据判断 | 1800 | 120 | 正例、对象错绑、版本/条件错绑、二手摘要、正文不足、相反记录与修订 |
| 缺口补查 | 800 | 80 | 未搜/失败/已读不足分开；有新查询、重复查询、应停止 |

共目标 **5000 条准入训练样本**，另按来源族分出开发与盲留出；生成候选量须更高，不能把候选条数写成训练量。每族训练占比上限 2%，归一化问题唯一率至少 90%，同一意图最多 3 种问法；每个角色分别报告这些数。教师只起草材料/目标，代码检验来源哈希、逐字跨度、完整格子、prompt/target 哈希、分区及 token 上限；涉及范围、冲突和补查是否真实推进的标签须独立人工抽审，高风险负例逐项审读。教师自审不计独立验收。

## 验证顺序与晋级门槛

1. 在训练前冻结**新的**真实自然问法盲集，至少 120 题：普通 30、多项目比较/选择 60、缺材料/版本冲突 30；包含知识库、联网及混合，但分别报告。旧 65 和旧 434 继续作为已见回归，绝不移出分母。新题对应的网页正文、知识库索引版本和候选池都保存快照；实时联网另记供应商变化，不用外网波动比较两个 State。
2. 用 7.2B 同一基座、同提示、同解码、同候选来源，先比较零 State 与规划 State 的**完整格子、每对象初轮机会、合法搜索式和普通题漏项**。再固定计划比较检索候选的相关性及一手来源覆盖；最后才看逐格证据与完整答案。供应商失败和未执行不能算“无证据”。
3. 规划 State 至少不得出现新增静默漏项；普通题的人工正确规划不能退步；大型题需要逐对象的候选覆盖与人工相关性共同改善。证据判断和补查分别在固定材料上做成对语义审读；同时记录新错引、新复读、新长度退出。质量审读、服务接入和正式晋级是三道不同结论。
4. 训练沿用经数值预检的 7.2B、RWKV kernel `fp32io16`、FP32 循环 State、冻结底模、物理 GPU3；角色 State 从零独立训练。预注册学习率 `1e-5`、2 epoch、梯度累积 4（位于用户给定 `1e-4` 至 `1e-6` 范围），仅在开发集选 checkpoint，不碰盲留出。新提示/协议、训练代码、数据和评测绑定均以哈希冻结，最长样本先做零更新前后向验证。

下一项工程前置是将已实现的规划协议接到**默认关闭的实验路径**，并把搜索请求的每批限速与全题待查格子分开；接线后冻结实际调用提示/State/解码与新盲集，才批量生成标签。当前 `task_matrix.py` 默认关闭且只按格子搜索、每轮最多两次联网，不能把旧 320 条合成 Planner 数据或把本方案的 5000 目标直接称为可训练样本。
