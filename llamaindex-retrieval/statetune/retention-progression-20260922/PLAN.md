# StateTune：补缺陷、保能力、继续推进

2026-09-22用户追加约束后的新设计。此前冻结的`defect-batch-20260922`保持不变，其12组试制仅检查基础生成协议；不再自动扩跑剩余628组。本文件是训练与数据修订设计，不是已执行训练或效果结论。

## 数据组织：围绕同一个问题的三个状态

不增加一长串缺陷分类。在已统计的缺陷上，每组材料同时考虑：

1. **正常完成**：没有该缺陷时，应直接做好原任务。覆盖普通事实、否定、数量/单位、表格、列表、多语言、多轮和正确引用；不能把旧模型的错误回答当保留目标，也不能把评测题搬进训练。
2. **缺陷发生**：只改变与该缺陷相关的材料或条件，训练正确识别、绑定事实和报告限制。没有证据、证据冲突、处理失败、任务未执行分别保留，不一律回答“不知道”。
3. **后续推进**：修正或补充材料后继续解决原问题。包括明确缺口、提出针对缺口的检索请求、读新增证据、修订判断、综合比较和完成后停止。补充仍不足时继续说明具体缺口，不能把每条轨迹都写成成功。

例如：正常抽取A/B同版本指标 → B指标缺版本，暂不能公平比较 → 针对B版本补检索 → 新材料明确版本 → 更新比较结论并逐项引用。另保留补检索无结果、发现真实冲突、用户撤回硬条件等分支；不固定为每组同样五步，也不把改名字当独立能力。

“下一步”是可观察的操作及其输入输出，不要求生成私有思维链。每步学生只能看到当时已有材料；后续来源不得泄漏到前一步。Writer仍只接收已选证据。缺口驱动补检索尚未接通生产，涉及新动作协议的样本须单独标为未接入，不能混入现有Atomic/Writer训练后宣称已支持该动作。

## 防止负向迁移

- 新训练版本必须包含正确的正常能力样本，不能只有失败补丁。三个状态的实际样本数、来源数和轨迹长度分别报告，不以固定配额凑数。
- 同一来源族的正常、缺陷、修复及后续全部留在同一分区。生成后继续检查语义/模板近重复；仅来源聚类不足以证明任务族独立。
- 已有测试题、标签、失败和题库成员关系原样保留；新训练材料排除已知评测来源。旧题用于回归，新留出用于未见验证，两者分别计分。
- 按部署角色分开编译和训练State；现有Resolver/Writer边界保持可审计。未经适配验证，不把窄协议State复用到Planner、联网选择器或其他节点。
- 对照固定7.2B、引擎、fp32io16、提示、解码、证据、预算和调用顺序规则，仅改变State。节点回放、完整固定材料问答、检索及联网端到端分别验证。
- 每个题库列出“基线正确→候选错误”的题ID、错引、漏答、误荐、复读、触顶和延迟。已确认新增错误先阻止晋级；不能用缺陷题或总体均分提升抵消正常题退步。漂移用重复对照区分，未解释漂移不算收益。
- 保留零State及历史模型作为对照和回退点。通过格式检查或同教师复核不等于语义验收；仅冻结开发集选候选，留出集不用于调参。

## 学习率与变量控制

用户指定学习率范围为`1e-4～1e-6`，即`1e-6 <= lr <= 1e-4`。此范围不自动解释为从最大值衰减到最小值。

首个训练候选采用固定`1e-5`。如需学习率对照，预登记固定值`1e-4 / 1e-5 / 1e-6`，相同初始化、样本顺序、更新步数和其他参数，仅按开发集及保留能力检查选择。不得同时比较数据配比、epoch和调度方式后将收益归因于学习率。若改为衰减方案，应另行冻结，不在运行中调整。

配套`TRAINING-CONSTRAINTS.json`是待训练适配器消费的约束，不是已经生效的训练命令。训练启动器还须验证有限数值、上下界、实际每步lr日志、只训练State以及FP32循环State；未完成这些检查不启动训练。
