# 检索与生成测试

在 `llamaindex-retrieval` 目录运行：

```sh
.venv/bin/pytest -q
.venv/bin/ruff check tests
```

测试通过自动 fixture 隔离本机 `.env` 和 `RWKVRAG_*` 环境变量。模型响应使用
`httpx.MockTransport`，检索使用内存替身，不要求启动 OpenSearch 或模型服务。

## 当前契约

- 查询语义由模型输出的结构化契约决定；无有效契约时保留规范化的原问题。
- 文档级 RRF 每个查询只使用一篇文档的最佳排名，不按特定对象或关系词加分。
- 抽取模型分别阅读每个源，代码验证字段、句子编号、逐字引用和内容哈希。
- Resolver 决定哪些证据进入 Writer；Writer 的输入保留源标识和引用正文。
- 默认不可变生成模式保留模型原文，包括缺失引用、错误引用、重复文本与空输出。
  诊断信息可以报告这些情况，但不能修改答案。
- 无选中证据时不调用 Writer；抽取异常和生成异常分别保留诊断信息。
- 对外返回数量与内部证据预算分别测试，知识库过滤条件传递到每条查询。

## 旧用例迁移

原来要求代码依据特定问法猜测对象、补充同义词、选择关系句、拼接答案或修复
引用的断言已替换。新的测试验证模型契约、传输、证据来源和输出不变性，不以
跳过旧模块的方式消除失败。单源评分和单源抽取测试明确指定对应模式，避免
默认启用的批量裁决模式与测试响应协议不一致。

`test_rag_pipeline.py` 使用真实的规划器、抽取器、生成器和服务编排，模拟外部
模型及索引，串联验证从多路查询到最终答案的证据来源。

这些是离线单元与流程测试。模拟模型选对证据只能证明代码遵循该决定，不能
证明真实模型一定选对，也不能证明当前 Wiki 数据完整。问答质量和换问法后的
准确率仍需要使用实际知识库、真实模型和人工确认的答案进行评测。
