# RWKV 检索架构规则

以下规则适用于所有当前应用问答入口；只允许 `rwkv` / `immutable` 链路。

1. 模型负责语义决定；代码只负责传输、切分、检索、排序、去重、格式解析和校验。
2. 禁止针对实体、题目或具体问法增加专用补丁、白名单、黑名单或语义词表分支。
3. 标准链路的 Writer 只能看到 Resolver 选中的逐字证据，不得看到未入选的检索候选。显式 `native_unified` 候选中，RWKV叶层从逐字原文选择证据并生成局部输出；子问题总数由模型根据任务决定，不得将归并输入上限当作拆分数量上限；并发数只限制同时执行的数量，其余任务排队。归并层每组最多3个直接子节点，只接收通过结构/绑定检查的模型派生raw及已选来源绑定；失败槽只传状态、ID/call/hash，不把其正文当作语义输入。失败raw仍在审计图完整保留，解析出的模型选择与程序校验准入分开记录。不接收未入选候选，不把摘要冒充逐字原文。trace必须区分实际原文输入与继承来源链；事实支持仍需独立审读。
4. RWKV 原始输出是不可变数据。代码不得增删、改写、补引用、删句或用兜底答案替换。
5. 校验和审计只能记录问题，不得改变对外答案。需要修复时必须发起有独立 trace 的新模型调用。
6. 每次模型调用必须保存精确 prompt、原始输出、内容哈希、输入证据 ID 和阶段耗时。
7. 所有实验固定索引名、索引版本、配置和提示词版本；一次只改变一个变量。
8. 先验证固定材料问答，再分别验证 Resolver、检索，最后验证端到端链路。
9. 连续正文切片必须有 overlap；表格行、列表项和 QA 对保持原子结构并携带父级上下文。
10. Writer 输出上限默认设为 2K token；输入证据容量单独配置，不与输出上限混用。

试用应用只保留 `flat`（`interactive-flat-quotes-v9`）链路，旧 parallel/lean/needs/funnel 试用链路已删除，不得作为选项或回退重新接入。
不建多层归并树：一次规划、并行阅读完整资料窗口、一次终答、一次核对。相邻同源窗口最多两窗合并，须先通过不生成文本的实际 token 预算检查；失败拆回原完整窗口，不截断或丢弃。短搜索摘要合并阅读。提示为纯文本：材料在前，日期、问题、
所问对象、信息项和指令在后；不传哈希、坐标或转义JSON。
规划输出本轮关系（新问题/追问/更正）；每个信息项须带用户原话中的逐字出处，代码子串核对，对不上的只记录不检索不作答。
`aspects`只用于让阅读多摘细节，不判定未知。多轮状态由代码保存：最近3轮的用户原话、整理后的问题、所问对象和上一轮回答首句（只用于指代消解，不作事实依据）；
追问先重读上一轮被摘抄的页面。不生成对话总结。
阅读输出逐字的回答句与细节句，代码在清洗后的阅读视图中做精确、忽略空白或忽略标点的子串绑定。先检查本次展示的全部窗口是否有完整引文；均无时，拼接句在全部已展示窗口按分句绑定并去重，不查未展示间隙。绑定失败的保留在审计记录中，不进入终答。
规划最多保留8个带原话出处的信息项，完整覆盖由模型负责。规划和阅读输出紧凑JSON；阅读仍检查全部资料与信息项，但省略没有引文的空条目。是否需要算术由模型的`calculation`决定，查询数值指标本身不触发计算调用。
网页阅读视图只做确定性清洗（去图片/链接URL/强调符号、HTML实体解码），原始快照另存；搜索摘要单独标明正文未核实。
终答输出answer/points/unknown三个字段，代码按顺序拼接展示，不改写措辞。核对是独立调用，问题须逐字引用原文才计入，只做标注、不改答案。
要点重复默认仍触发一次独立重生成；显式配置`retry_repeated_points=false`时只记录重复诊断并交付第一次原回答，不删句、不改写、不隐藏原输出，也不把样式诊断当作事实核验。
阅读引文的字符上限按实际展示材料长度设置，避免强制截断完整条件句；JSON语法/类型失败或长度耗尽最多发起一次独立重读，失败原帧保留，不补括号、不使用半帧证据。名称字面匹配只用于检索和审计，不能据此判定不同语言名称指同一对象或强制拒答，也不向Writer追加代码推断的对象来源映射。
结构化生成使用语法EOS，清空聊天stop串；只在输入未含聊天分隔符时约束自由字符串不生成该分隔符，保留原有pattern、enum和const。完整Schema仍由应用验证。
发布时间和抓取时间分别传递到Writer。时间由代码换算为北京时间并标注相对提问日；仅含日期的元数据保留日期粒度，不补时刻。上传资料较少时全部阅读，较多时只按标题与对象名字面匹配选取。
旧 `existing` / `legacy` 链路及其专用规则模块已删除，不得作为可选功能、兼容包装或失败回退重新接入。冻结历史实验只作为审计记录保留，不从当前应用恢复执行。模型的 `NONE`、拒答和非法引用只能如实保留或标记失败，代码不得强行补入证据或改成成功答案。

显式配置`live_progress=true`可在job接口提供实际执行事件（规划、取材、资料进入、阅读调用、逐字绑定及终答）。观测回调接收隔离副本，其修改或异常不得改变模型输入、输出或证据选择；事件不含语义核验通过承诺。前端须区分未执行、运行中、失败和完成，按operation配对调用，不能用计时动画推演完成。`flat_web_include_domains`仅限定网页检索来源范围，默认不限定。

### 用户选择的网络来源范围

试用接口允许每次问题显式指定 `web_include_domains`，仅接受域名；未指定时沿用服务配置。演示配置可显式启用 `flat_web_scope_query`，把这些域名作为 `site:` 检索范围交给提供方，同时保留返回URL域名校验。原模型query与实际provider_query分别记录；范围不提供正文、期望答案或按问题改写语义。禁用时保持既有查询行为。并发配置上限扩展至1024只允许表达已验收的多实例容量，默认仍32，实际容量与吞吐必须另行实测。

阅读没有直接回答句不等同于事实缺失：已选细节仍交由Writer判断是否能推导。模型规划要求计算时，允许仅依据明确题设数值进入计算与终答；题设须标明，不冒充来源事实。无引文且无计算要求时仍保留无证据结果。

阅读、计算、终答和核对同时保留用户本轮原话与模型整理问题；整理问题不能使题设数值、条件或否定丢失。
计算结果传给Writer时保留计算记录中的数值，不用默认六位有效数字格式把大整数静默舍入。

显式`read_require_assessment=true`可要求至少一个阅读判断条目；无依据仍可生成两组空引文，不能把非空条目当成有证据。默认关闭。显式`final_response_style="concise"`让Writer将完整回答放在answer、生成空points，并保留unknown；由模型依照新契约重新生成，不能删改既有原回答。两种契约的质量和性能都须单独验证，不能继承默认链路的结果。

阶段提示集中在`flat_prompts.py`。训练数据准备应使用同版本阶段提示、聊天模板和字段结构，并保留原记录与迁移记录的区别。简短终答使用独立提示，不叠加标准模式的要点数量要求；`unknown`始终为字符串。只有实际计算成功时才追加计算说明，普通来源事实不标成题设假定。规划须保留用户给定的版本、日期、平台和事件，假设只写确实未明确的条件。假设行只供Writer说明采用的理解，不规定回答开头。规划要求计算时，计算阶段至少输出一条算式；没有成功的代码计算结果时，Writer不得自行心算新数值，需计算的要求写入unknown。搜索结果窗口超限时默认读取前缀窗口；显式`window_selection="literal_terms"`只按字面出现的所问对象、指标或检索词挑选其余窗口，首窗口始终保留，属于检索而非对象判定。

用户指定网页与上传资料使用相同的每来源窗口数量上限；普通搜索所得网页仍使用搜索窗口上限。阅读输出预算随当前资料与信息项数量调整，长度耗尽时的独立重读可提高预算；全部调用继续遵守完整窗口输入检查，不能补闭合符号或截取半份JSON作为证据。

终答要点可保留代码中的方括号，用反引号标记代码；引用审计忽略代码里的数字下标，不改原回答。计算算式仍由模型给出，代码仅执行受限数值AST（四则、乘方、sqrt/log/ln/log10/exp/abs），检查完整数字与题设/原文绑定、复杂度和有限实数；不补公式或题目答案。浮点结果保留实际数值，不以固定小数位把微小量变成零。
