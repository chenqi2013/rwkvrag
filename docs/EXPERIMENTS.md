## 已完成登记：只改变输出标签

假设：证据支持判断的 YES/NO 可能与原问题的肯定/否定含义混淆。实验只测这个假设，不同时加训练、换模型或改检索。

| 项目 | 固定或变化 |
| --- | --- |
| 模型与 State | 固定 7.2B 同一 checkpoint，zero State；运行前核对身份/权重来源 |
| 任务语义 | 固定“这份证据能否回答指定问题”，否定答案仍可作为有效证据 |
| 两组唯一差异 | YES/NO 与 ANSWERABLE/INSUFFICIENT；只改标签及必要的输出格式声明 |
| 提示其余内容 | 使用同一 strict-v1 内容，不添加示例、解释、特殊规则或字段 |
| 输入 | 相同问题、原文、上下文、来源 ID 与顺序；标签转换只发生在格式声明，不能替换原文里的 YES/NO 字样 |
| 模板与传输 | 相同 canonical envelope、前缀、tokenizer、BOS/EOS 和 stop_tokens |
| 解码与预算 | 固定 greedy argmax；请求温度 0、传输 0.001 均不参与该服务选词；相同输入上限、32-token 输出预算、并发 1、超时和重试策略 |
| 数据 | 新材料与标签先冻结，成对例不跨集合，模板族隔离；旧 40 条为已见回归资料 |
| 评分 | 语义标签一一对应；只按事先声明的精确格式解析，不修补、不用新模型重判成正确 |
| 不做的联动 | 本轮不调整切分、检索、候选排序、Writer、训练 State 或正式运行配置 |

## 执行和计分

- 每条保存准确 prompt、原始输出、来源和哈希、finish reason、耗时。
- 不根据中途结果修改材料、提示、解析器或门槛。必须修改时结束当前试验，保留失败，新开版本。
- 分别统计误选、漏选、格式/运行失败、精确率、召回率、成对正确率；同时列出按类别与集合的结果。
- 无效输出保留在分母中，不转换为 NO/INSUFFICIENT；不只报告“正确 JSON 比例”。
- 当前小样本门槛仍是完整执行、无非法输出、零误选、召回率及成对正确率均至少 90%；还要检查负向迁移。
- 若只减少误选却明显增加漏选，不宣布整体胜出。新标签若导致格式错误，也算真实代价。
- 服务变化、输入超限、运行中绑定哈希变化要标为受污染或未完成，不能混进干净对照。
