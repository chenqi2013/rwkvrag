1. 记录假设、唯一变化、基线、候选与晋级门槛。新实验使用新目录和版本，不修改旧冻结文件。
2. 完成标签复核，说明谁编写、谁复核以及仍未解决的歧义。没有独立复核时如实标注，不能声称已独立验收。
3. 提交并保存数据/脚本/prompt/配置哈希；明确未见验证与已见回归的范围。
4. 核对模型身份、State 兼容、实际输入/输出预算及服务可用性。健康失败要单列，不能计成模型语义拒绝。

## 执行和计分

- 每条保存准确 prompt、原始输出、来源和哈希、finish reason、耗时。
- 不根据中途结果修改材料、提示、解析器或门槛。必须修改时结束当前试验，保留失败，新开版本。
- 分别统计误选、漏选、格式/运行失败、精确率、召回率、成对正确率；同时列出按类别与集合的结果。
- 无效输出保留在分母中，不转换为 NO/INSUFFICIENT；不只报告“正确 JSON 比例”。
- 当前小样本门槛仍是完整执行、无非法输出、零误选、召回率及成对正确率均至少 90%；还要检查负向迁移。
- 若只减少误选却明显增加漏选，不宣布整体胜出。新标签若导致格式错误，也算真实代价。
- 服务变化、输入超限、运行中绑定哈希变化要标为受污染或未完成，不能混进干净对照。
