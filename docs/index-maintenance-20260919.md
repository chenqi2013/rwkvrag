# 知识维护第一批：失败不破坏活动索引

日期：2026-09-19。后续已补充 [索引版本查看与回滚入口](index-rollback-20260919.md)；下文保留第一批交付范围。范围是索引发布安全，不是全部知识版本管理或自动 Wiki。

## 行为变化

旧流程在文件重建前删除旧切片，全库重建前删除整个索引。新流程先写独立版本、刷新并校验，然后切换检索入口。切分、写入、复制或校验失败时不会删除活动版本。

- 文件上传/重建：复制其他文件的切片到新版本，再写入本文件；本文件旧切片不带入新版本。空文档不会替换已有文件。
- 全库 `--recreate` 与 SQLite 重建：新版本完全构建成功后发布；拒绝发布空索引。
- 已有物理索引无须删除或重命名。应用首次启动创建 `<配置索引名>-active` 别名，指向原索引；之后的新版本名为 `<配置索引名>-v-<UUID>`。
- 别名移除与添加在同一次原子请求中完成。机制依据 [OpenSearch Manage Aliases API](https://docs.opensearch.org/latest/api-reference/alias/aliases-api/)。
- 原版本和失败的暂存版本均保留；发布请求超时也不猜测结果、不清理可能已激活的索引。
- health 返回 `index`（活动别名）、`configured_index` 和 `index_version`（实际物理版本）。

## 写入与恢复约束

所有本应用的导入、重建和删除都使用同一索引级写锁。锁通过原子创建 `<配置索引名>-write-lock` 索引取得；冲突的操作明确失败，可在现有任务完成后重试。锁覆盖整个导入过程，避免重建快照遗漏并发写入。服务停止时等待后台写入线程退出，再将任务标记为可恢复。

进程被强杀可能遗留锁。此时读取仍可用，后续写入会失败；**不自动按时间抢锁**，避免旧进程恢复后覆盖较新数据。运维必须确认所有写入进程已停止、核对活动别名和后台任务后，才可清理遗留写锁并重试。当前还没有自动恢复控制台。

首次部署必须停止所有旧版应用和导入脚本后统一升级。旧版仍直接写物理索引，不参与锁；混合运行不能保证更新不丢失。其他外部工具也不能绕过别名和应用写锁直接写入底层索引。

## 验证

真实 OpenSearch 测试只操作随机前缀 `rwkvrag-test-versions-<UUID>`，不切换实际业务索引。覆盖：

- 接管原有索引与成功发布后保留原版本；
- 写入中途失败、空输入、复制失败；
- 文件替换保留其他文件并清除本文件旧片段；
- 发布前超时及发布成功但响应丢失；
- 两个实例竞争写入、删除、重建；
- 遗留锁不被自动抢占；
- 取消任务等待写线程结束；
- 从管理任务入口实际执行文件重建的成功与故障路径。

运行（服务地址按环境替换）：

```bash
cd llamaindex-retrieval
RWKVRAG_TEST_OPENSEARCH_URL=http://127.0.0.1:18438 \
  .venv/bin/pytest -q tests/test_index_versions.py
```

12 项真实 OpenSearch 故障及任务测试通过；相关解析、导入、管理路由和存储回归 57 项通过。服务测试的 42 项失败在改动前后完全相同，另有 36 项通过；保留对照日志，不声称全仓库测试通过。详见 [验证记录](../artifacts/index-maintenance-20260919/)。

## 尚未完成

- 文档正文编辑、业务版本号、跨 MongoDB 与 OpenSearch 的一致性恢复、用户可操作的版本回滚。
- 真正的增量索引：目前文件重建复制整个索引中其他文件，时间与磁盘成本随语料增长；需要容量评估。
- 历史版本自动清理；现在为避免误删而保留所有版本，需要监控磁盘。
- 多实例任务认领与租约；本批索引写锁仅保护索引，不解决任务状态的所有竞争。
- 一次问答跨多个检索调用的版本固定；别名切换是原子的，但多个先后调用可能跨越一次切换。
- Wiki 生成、来源依赖、修订和过期处理；回答质量、OCR、Agent 等其他方向仍按原状态待做。

全库 `recreate` 仍意味着用本次输入替换整个配置索引，不能误当成单个知识库的增量导入。旧版本保留不等于 MongoDB 文件记录也自动回滚。

本批未重启业务应用，未修改实际知识库索引。首次上线需统一升级写入端并验证真实业务流程。
