# RWKV 2.9B StateTune 实践经验

这轮 statetune 从真实运行的 trace 出发：定位错误，把错误改成有依据的正确输出，再生成训练数据，最后用相同问题比较训练前后的表现。以下记录截至2026年9月11日，重点是问题来源、数据生成、训练方法和实际效果。

## 问题从哪里发现

我们逐阶段检查模型收到的完整输入、证据、原始输出和最终答案，发现了几类反复出现的问题：Reader漏选支持答案的片段；Writer混淆单位、年份和版本，多问漏答，引用错位，缺少证据时仍然编造；Planner输出不符合结构要求，长历史中丢失当前任务；部分回答持续重复，直到达到长度上限。

这些问题不是只看训练loss就能发现的。必须回到trace，确认模型当时看到了什么、哪个阶段做错，以及错误是否已经影响后续阶段。Reader没有选入答案与Writer拿到证据仍答错，需要不同的训练样本。

## 怎么生成数据

我们保留失败调用的原始问题、历史、证据和错误输出，只依据该阶段实际可见的证据编写正确输出，形成了17条独立复核的纠错种子。错误输出只留作分析记录，不作为模型学习的目标。

围绕种子扩展出2000条数据：Writer1400条、Reader450条、Planner150条。扩展时变化对象、数值、单位、版本、证据位置、历史更正和缺失条件，让同一种错误机制出现在不同场景中。

其中774条重新构造输入，1226条复用已复核的受控实例并建立种子关联，因此不能把它们称为2000个自然发生的新问题。父种子提供构造指导，也不表示每条派生数据覆盖了该种子的全部缺陷。

训练真实来源313页与通用评测所用30页按来源文档隔离。已经用于纠错的旧题单独作为暴露回放测试，避免把记住训练种子当作泛化能力。每条数据保留prompt、target、来源和关联trace的哈希；人工构造场景明确标注。

## 怎么训练

训练使用服务器上的RWKV-PEFT，底模固定为RWKV7 G1j 2.9B（`rwkv7-g1j-2.9b-20260831-ctx16384.pth`），在物理GPU3执行。训练入口与数据由本项目管理，模型实现使用已冻结的RWKV-PEFT源码。

训练与推理对齐提示词、Assistant前缀、换行边界和EOS。Writer/Reader的Assistant前缀保留末尾换行，Planner使用无末尾换行的对应协议，三阶段不能混用。Prompt和target分别编码；prompt部分不计算目标loss，只监督正确输出及其结束符EOS=0，并按next-token方式移动标签。

每组独立从零state开始，只训练32层FP32初始state，共5,242,880个参数，底模保持冻结。统一使用1 epoch、学习率1e-5、梯度累积2、随机种子20260911。优化器使用AdamW（weight_decay=0），梯度L2裁剪上限1.0。最长训练行先做零更新反向预检。

| State | 样本数 | 优化器更新次数 |
|---|---:|---:|
| Writer100 | 100 | 50 |
| Writer300 | 300 | 150 |
| Writer600 | 600 | 300 |
| Writer1400 | 1400 | 700 |
| Reader450 | 450 | 225 |
| Planner150 | 150 | 75 |

Writer四档使用嵌套子集。它们不额外增加2000条唯一数据的总数；计入子集重复实验，共3000次样本反向计算、1500次优化器更新，另有6次零更新预检。每组训练结束后核验，底模1062个张量均保持不变。

## 训练后的表现

### Reader：证据判断有明确改善

在60道新的受控阅读挑战中，正确判断从零state的48/60提高到Reader450的60/60。说明这批训练改善了本组任务的证据判断，特别是此前漏选的正例。

但真实调用中仍会误选纯标题等不含答案的片段。这个60/60不是所有真实资料上的准确率，也不能据此认为证据选择已经可靠。

### Writer：失控重复减少，正确性没有随数据量单调增加

在相同的200道通用题中，输出终止情况如下。正常EOS不等于答案正确。

| 训练量 | 正常EOS | 达到长度上限 |
|---|---:|---:|
| 零state | 155 | 45 |
| 100条 | 171 | 29 |
| 300条 | 196 | 4 |
| 600条 | 200 | 0 |
| 1400条 | 199 | 1 |

我们又对输出前固定的36道题、每题五档，共180份回答做了独立语义复核。这里要求回答完整、引用有依据、没有失控重复；允许少量有依据的冗余、繁体引用和能辨认来源的非标准引用。这是事后独立复核，不是盲评，也不是全部200题的语义准确率。

| 训练量 | 有据可用 |
|---|---:|
| 零state | 10/36 |
| 100条 | 12/36 |
| 300条 | **17/36** |
| 600条 | 14/36 |
| 1400条 | 15/36 |

在这份固定抽样中，300条最好，继续增加到1400条没有获得持续提升。少量有据冗余与错值、错引、漏答分开判断；例如混入另一个对象的光谱分类，不能仅因来源中存在这句话就算正确回答。

| 分组，每组4题：有据可用 | 零state | 100 | 300 | 600 | 1400 |
|---|---:|---:|---:|---:|---:|
| 单字段 | 2 | 4 | 4 | 4 | 3 |
| 多字段 | 3 | 3 | 4 | 4 | 4 |
| 历史更正 | 0 | 1 | 3 | 2 | 3 |
| 部分缺失 | 1 | 1 | 2 | 1 | 0 |
| 空证据 | 0 | 0 | 0 | 0 | 0 |
| 无关证据 | 2 | 2 | 2 | 1 | 2 |
| 表格 | 1 | 0 | 0 | 0 | 1 |
| 版本 | 1 | 1 | 2 | 2 | 2 |
| 冲突 | 0 | 0 | 0 | 0 | 0 |

单字段、多字段和部分历史更正有所改善，但空证据、资料冲突两组各4道题，所有档位均未通过。部分缺失仍会被忽略或编造。表格中旧版数值混入新版、日期交叉归属、正确数字配错资料编号仍然存在。有些回答只是把长篇幻觉缩短了，没有变成可靠拒答。

另一组8道新Writer挑战中，当前要求正确完整数为零state/100/300/600/1400 = 6/4/4/4/0。它与通用36题属于不同题集，不能混成一个分数；也提示1400档在复杂表格与部分缺失任务上出现了退步。

### Planner：本轮出现退步

24道新挑战中，合法结构输出从零state的21/24降到Planner150的16/24。后续15道真实RAG问题中，Planner150也全部出现解析或长度失败，实际触发原问题回退。

例如模型输出了`queries: ... / fields: ...`，而不是要求的JSON。训练目标与输入传输格式已经对齐，但模型仍未稳定遵守输出协议。回退之后其他阶段答对，不能算Planner训练成功。

## 这轮得到的经验

真实trace决定该训练什么；纠错种子必须依据当时可见的证据；输入协议一致是必要条件；输出格式、结束行为与答案正确性必须分别评估。不能只凭loss下降、答案变短或训练数据增加判断效果。

这轮证明statetune能够改善部分能力，也表明收益会随训练规模和任务类型变化。Writer300在固定材料抽样中较好，不代表已经验证它在完整RAG中最优。本轮仅比较一轮固定训练参数，观察到的是当前数据与配置的瓶颈，不能据此认定达到RWKV 2.9B或statetune的能力上限。
