# 对比问题质量修复与验收（2026-09-19）

## 结论

已部署原始问题保留和有上限的规划格式重试。**对比答案质量仍未通过验收**：Reader 会漏选另一方证据，Writer 会漏答、串引用，空材料还可能产生不存在的来源。不能把 HTTP 成功或 `completed` 当作内容正确，更不能据此宣称达到商用品质。

## 已部署的链路修复

1. `native_preserve_original_question=true`：纯知识库检索也保留原始问题，和模型规划的查询去重后分别检索、交给 Reader。原始规划不改写，知识库过滤条件保持有效。用于防止规划只留下一个对比对象。原始问题增加一路检索，在当前 per-query 配置下最多增加一组 Reader 预算；它不保证模型理解多轮指代或接受所有正确证据。
2. `native_planner_format_repair=true`：仅当 Planner 正常生成但格式校验失败时，进行一次独立模型重试，提示合法结构和数量上限。保存两次原始输出、精确提示、校验错误和修复关系。失败继续保留原问题回退并记录 `planner_partial_failure`；超时或截断不会当作格式错误重试。不会通过代码展平数组或截取查询来假装规划成功。

两个开关在通用 Settings 中默认关闭，以保持旧部署的调用预算；本机正式服务已启用。Writer 仍使用 `writer-trace-300` + `evidence_first`，Reader 仍使用 `reader-trace-450`，引用前端沿用 citations-20260919 构建。
