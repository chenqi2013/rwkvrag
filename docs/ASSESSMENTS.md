# 独立证据判断记录：接入设计（尚未实施）

> 本文维护的是后续接入设计，不是当前实现清单。当前状态见 [CURRENT](CURRENT.md)，下一轮实验约束见 [EXPERIMENTS](EXPERIMENTS.md)。

## 目标

把“证据原文保存正确”和“证据真正回答了问题”分成两个可独立验收的环节。未来有更好的 RWKV checkpoint、State 或其他模型时，只替换判断组件，复用原文位置、来源版本、历史记录与前端引用。

固定材料上的四组成对评测已完成，结果见[报告](archive/2026-09/evidence-support-results-20260920.md)。生产接入、StateTune 训练和新的分子/总结层不在这一轮中直接上线。

## 先固定判断语义

一次调用只检查一个问题和一份短证据。YES 表示该证据和随附上下文能回答这个问题，且明确的对象、属性、时间、地域、模式和版本条件均相符；不表示“事实是真的”，也不表示对是非问题回答“是”。

例如：

- “不允许自行换电池”可以支持回答“是否允许自行换电池”。
- “尚未统计退货数”不能支持具体退货数量，也不能被变成 0。
- 同一型号在另一国家的价格不能直接支持当前地域售价。
- “模式 / 续航”表头提供解释上下文，但没有数据行就不能回答续航时长。

来源真实性、两个来源的冲突关系、最终采用哪份证据，是后续独立任务。不能让一个 YES 同时承担相关性、真实性和权威裁定三个含义。

## 证据记录与模型判断分开保存

当前 source claim 已包含保存原文、哈希、位置、索引版本与原始调用。下一次接入新 Reader 时，应增加独立的 assessment，而不是覆盖旧标签或修改旧来源：

| Assessment 字段 | 用途 |
| --- | --- |
| id / evidence_id / evidence_sha256 | 精确绑定哪条原文 |
| request / request_sha256 | 精确绑定这次问题与条件 |
| protocol / prompt_sha256 | 解释判断依据，区分新旧任务契约 |
| checkpoint / checkpoint_sha256 | 识别模型；缺哈希时明确标为未核实 |
| state_id / state_sha256 | 绑定与 checkpoint 兼容的 State |
| decision | supported / unsupported；仅接受完整有效模型输出 |
| execution_status | completed / invalid / timeout / failed；异常不能冒充 unsupported |
| call_id / raw_output / finish_reason / elapsed_ms | 保留审计证据 |
| supersedes_assessment_id | 可选的新旧判断关联；原判断仍保留 |

这是后续接入契约草案，本轮没有新增线上 assessment 集合。新模型判断与旧模型不同，应作为可展示的分歧，不由代码静默替换成“更正确”的事实。

缓存键必须包含原文哈希、问题/条件哈希、协议、checkpoint 和 State。任一项变化都不能复用旧判断。物理索引版本一致也不能代替原文内容哈希。

## 已完成评测的背景（2026-09-20）

40 条材料组成 20 对，每对只有一个相关差异。开发与验证各 20 条，同一对不跨集合；全部材料、标签、提示与门槛在调用模型前冻结并提交。标签为人工构造、由编码助手预先编写，后续训练前需要独立审阅。

固定四组：2.9B Reader450 + 现有提示、2.9B Reader450 + strict-v1、7.2B zero State + 现有提示、7.2B zero State + strict-v1。同一模型/State 内只比较提示变化。跨两种模型时同时改变了 checkpoint 和 State，不能把差异简单解释为参数量收益。

统计误选、漏选、格式/运行失败、精确率、召回率和成对正确率，分别查看开发/验证和各类别。非法输出不会被修成 NO，也不会从召回率分母中消失。

小样本试验门槛：完整跑完、无非法输出、零误选、召回率至少 90%、成对正确率至少 90%。即使通过，也只进入更大样本与实际检索验证，不能直接证明商用质量。

## 后续接入的决策原则

1. **如果仅换提示有效**：在新的未见材料上确认收益，再单独接入 assessment，不改 Writer 与证据内容。
2. **如果 7.2B 更好但仍有漏答**：先比较错误类别和调用成本，不能为了精确率把所有困难问题都拒绝掉。
3. **如果两个模型都存在同类问题**：先检查任务语义、问句表达与标注一致性，再制定 StateTune 数据，不用实体关键词补丁掩盖错误。
4. **如果模型分歧明显**：研究分歧复核的价值；增加一次调用必须带来可测量收益，不能默认堆叠模型就会更好。
5. **更强模型出现时**：运行同一契约和回归，再补全新的未见材料。通过后才进入实际检索、冲突分子和分层总结。

评测材料一旦用于分析或训练，就成为已见开发/回归材料。不能继续称为盲测，也不能把同一数据上的改善当作泛化能力。
