# 多项目比较逐层 Oracle 诊断 V1

2026-09-23 完成独立的[预登记与输入](../../../llamaindex-retrieval/eval/layered-oracle-20260923-v1/PLAN.md)。四组作者编写的虚构产品材料分别有 2、3、4、6 个项目；每组单独测试「原始证据→事实五元组」「人工核准事实→资格/推荐」「人工核准决策＋已选逐字证据→Writer」。12 个成员，7.2B 同一基座，零 State／训练 State 双轮，共 48 份原始回答。第二轮与第一轮在每个题×组的原文、token 和停止原因完全一致，因此只有 4 个不同场景，不能把 8 份同组输出当成 8 道独立题。

新题由本轮另写，没有复用训练样本或冻结的 GitHub 题；这些是作者设计的短材料，不是未见真实项目泛化、知识库召回、联网检索或产品准确率。GPU3 使用当前原生 fp32io16 引擎；独立服务成功退出，原冻结旧题队列保持运行。确切输入、配置、模型 State 哈希、48 份原始输出、停止原因及逐文件 SHA-256 在[证据目录](../../../artifacts/layered-oracle-20260923-v1/MANIFEST.json)。输入和评分脚本在调用前已以提交 `f0f480b1` 上传 GitHub；原始文本不修补。

## 预登记严格结果

下表按**第一轮 4 个不同场景**列示；第二轮数字相同。格式失败没有偷偷转换成有效答案。

| 独立任务 | 零 State | 训练 State | 解释 |
| --- | ---: | ---: | --- |
| 事实抽取完整五元组、严格 JSON 对象 | 0/4 | 0/4 | 零组 4/4 输出数组而非对象；训练组 1/4 输出数组，另外场景仍有事实错漏。 |
| 正确事实→完整资格、推荐 | 0/4 | 0/4 | 两组都无法完整通过。 |
| 正确事实→项目资格判断 | 6/15 | 4/15 | 训练 State 在这批材料上更差；项目层统计，不是 30 个独立项目。 |
| 正确事实→推荐集合 | 1/4 | 0/4 | 训练组更差。 |
| Gold 决策→Writer 正常停止 | 4/4 | 4/4 | 短 Oracle 材料都自然停止；不能外推到大型 README。 |
| Writer 有来源引用 | 0/4 | 0/4 | 16 份双轮回答一律没有引用。 |

实现者逐份复看 8 份不同 Writer 回答并绑定原文哈希：完整保留 Gold 资格与推荐，零组 1/4、训练组 3/4；所有事实均可由已选文字支持，零组 1/4、训练组 2/4；含引用且完整的回答两组都是 0/4。训练组在 6 项目题中重复列错项目、漏掉「木桥 Cloud」；零组把 GPU 偏好误作硬条件、把未检查的 Windows 误作已满足。人工判断**非独立盲审**，短例的 Writer 内容优势不能抵消上游资格退步和无引用。

[严格逐份评分](../../../artifacts/layered-oracle-20260923-v1/score-v1/DETAILS.jsonl)保留了 JSON 结构错误、事实漏/增和项目状态错分。[Writer 人工判决](../../../artifacts/layered-oracle-20260923-v1/writer-review-v1/REVIEW.jsonl)有每份不同回答的理由及哈希。前端现有格式层对这 16 份无引文 Writer 回答显示为 16/16 可见：它检查非法编号和长复读，没有把“证据存在但回答完全不引用”作为拦截条件。这是本轮发现的展示门缺口，不是模型答案已经可靠。

## 单列的事后内容分析

看见零组常输出 JSON 数组后，另做[事后探索](../../../artifacts/layered-oracle-20260923-v1/posthoc-v1/SUMMARY.json)：仅为分析而把数组视作 `facts`，重复事实去重，再计算内容五元组；**不修改原回答，也不改变上述严格失败结论**。第一轮事实命中数零组 39/47、训练组 37/47；两组各有 1/4 场景在这种事后归一后全部正确。4、6 项目场景仍出现值、来源和版本状态错误，故单靠改外层 JSON 格式不能解决整个问题；场景内容也同时变化，不能把退化单独归因于项目数量。事后评分选择受观察结果影响，不作为晋级依据。

## 当前能与不能下的结论

1. 在**正确事实已经直接给出**时，资格与推荐仍失败，这是独立于检索召回的 Comparator 缺陷；真实检索仍可能另有问题，不能据此排除。
2. 事实抽取同时有格式和内容缺陷；把 0/4 全解释为“读不懂材料”不成立，正因如此分别保存严格与事后指标。
3. Gold 决策改善了短回答收束，但没有让模型按要求引用；自然停止不是可靠回答的充分条件。
4. 多层都可同时损坏，没有证据支持唯一“第一根因”。这批短虚构题不能证明训练 State 在真实大型比较上有效；[已有 24 题真实 README 验收](state-fresh-github-paired-20260923.md)仍是大型比较未通过，候选不切正式模型。

下一实验应冻结新的真实项目来源、逐字 Gold 片段和来源隔离绑定，分别比较真实检索材料、人工选片段与完整文档；再做顺序/名称扰动和 Gold 决策 Writer 引用诊断。旧题队列继续完成，所有新增材料与题目继续隔离训练，且不修改本 V1 的输入或原始失败。
