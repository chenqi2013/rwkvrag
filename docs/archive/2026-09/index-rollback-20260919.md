## 已实现

- `index-versions`：只读列出活动版本、曾经活动的保留版本、未验证的暂存版本。
- `rollback-index`：在索引写锁内检查预期当前版本，原子切换到曾经活动的版本；保留切换前后的索引。
- 原活动版本在退出前持久记录所属配置索引及活动资格；失败留下的新索引不因此获得回滚资格。
- 回滚拒绝外部索引、通配符、别名、未验证的暂存版本、空索引，以及包含失败分片的计数结果。
- 必须传入 `--expected-current`。若其他操作已经切换版本，命令失败，要求重新查看；不会按旧页面或旧命令覆盖新版本。
- 切换响应超时时保留两个版本，操作者重新查看活动入口确认结果，不自动删除或反向切换。

## 使用

使用与目标应用相同的服务地址、认证和 `opensearch_index` 配置。从 `llamaindex-retrieval` 目录运行：

```bash
.venv/bin/python -m llamaindex_retrieval.cli index-versions

.venv/bin/python -m llamaindex_retrieval.cli rollback-index \
  --target '版本列表中的完整旧物理索引名' \
  --expected-current '刚查看到的完整活动物理索引名'
```

返回中的 `scope` 固定为 `entire_search_index_only`。版本列表中的 `rollback_eligible` 表示曾为活动版本；执行时还会重新验证当前版本、目标可读性和非空状态。

本批通过命令行运维入口提供功能，没有增加可由普通知识库用户调用的全库回滚 HTTP 接口。

## 范围与限制

**回滚作用于整个配置索引，可能包含多个知识库；不是单文件回滚。** 回滚到删除操作之前的版本会使当时的检索内容重新可见，也会撤回该版本之后的检索更新。操作者应先核对版本范围。

此操作不恢复 MongoDB 文件记录、上传的原文件、文件统计或权限记录。命令输出明确返回 `original_files_restored=false` 和 `database_records_restored=false`。完整产品级回滚仍需要文档版本、数据库一致性恢复与权限联动，不能用本命令代替。

先前已生成但没有活动资格记录的历史索引保守标为 `unverified`，不自动认定其构建成功；当前版本在下次退出前会记录资格。旧版本仍无自动清理策略，需保留磁盘余量。版本名中的 UUID 不是时间顺序，列表提供创建时间。

沿用第一批部署要求：所有写入端统一升级，禁止混用直接写物理索引的旧版应用；进程强杀遗留的锁需要人工核查后恢复。只读版本查看不会初始化别名、创建锁或修改映射。
