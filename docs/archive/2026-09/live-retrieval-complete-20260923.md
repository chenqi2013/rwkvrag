- **单项目也会错引。** 新题 45 要求 FastAPI 官方文档与仓库，模型给出两个链接并都标 `[资料 1]`；最终 `[资料 1]` 是官方教程页的 VS Code 扩展摘要，不含仓库地址。题 47 要求 pgvector 官方安装说明，搜索前两条是 CSDN/知乎教程，最终无来源却输出 `[资料 2]`。题 48 要求 SGLang 官方发布说明，最终引用知乎对比文章并回答“移植指南”。这些是来源与要求不匹配，不以链接看似正确判通过。

- **自动路由可触发联网，覆盖仍失败。** 题 62 的 `auto` 路由选择 `hybrid`，最终两条来源只涉及 WeKnora，RAGFlow、Dify 没有各自资料；题 63 的 llama.cpp 官方仓库问题最终引用博客园教程。

上述是实现者审读的诊断样例，并非 65 题人工全量语义打分。自动统计的对象名覆盖和引用编号只检查字面形态，不验证结论是否由选中原文支持；本轮不报告“准确率”。

## 判断与下一步

当前单仓库联网接口已接通，但**复杂比较和普通出处题都尚未达到可信体验，更不能当作可商用质量**。优先解决四个可分离问题：① 上游引擎失败时暂停/切换提供方，避免 HTTP 200 空结果持续消耗请求；② 将“每个项目×待查维度”的待查格子与实际搜索预算分开，使用短的项目专属检索词并公平补查；③ 对官方资料优先排序并获取可核对正文，不能只给前两条二手摘要；④ 最终答案逐断言绑定已选证据，空证据或部分项目未查时明确指出缺口，防止无来源推荐与假编号。任何实现都要在相同旧题与新题上回归，并把供应商故障与模型质量分开。
