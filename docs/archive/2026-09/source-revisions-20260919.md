## 本批完成

上传文件入库和重建现在先生成独立快照，再从快照解析、切分并构建新索引。

1. 保存原文件的完整字节，不把解析文本当成 PDF/DOCX 原文件；原文版本由 SHA256 标识。
2. 保存解析结果 JSON，包含准确的解析正文、文档 ID、元数据、解析器源码哈希和原文快照地址；JSON 本身也有 SHA256。
3. 每个新切片携带原文版本、原文 SHA、解析快照 SHA 和各自地址，以及解析正文哈希。溯源字段排除在 LlamaIndex 的默认模型元数据之外。
4. 新索引的映射元数据记录前一索引、被替换文件、本次来源快照及任务 ID；保留旧切片时同时保留其原有来源标识。
5. 索引发布成功后，文件记录才写入 `last_indexed_revision` 和 `last_indexed_index_version`；文件管理 API 保留这两个可选字段。它们表示最近成功入库，不冒充索引回滚后的当前状态。
6. 原文件与上传记录哈希不符则拒绝重建，不把直接修改磁盘文件伪装成正式修订。

同一内容重复入库复用快照，不覆盖已存在的文件；已有快照被篡改时拒绝覆盖。写入通过临时文件、fsync 和原子硬链接发布；失败的暂存文件会清理，已完整生成的快照保留。

## 查询指定索引的来源

使用与目标应用相同的配置，从 `llamaindex-retrieval` 目录执行：

```bash
.venv/bin/python -m llamaindex_retrieval.cli index-versions
.venv/bin/python -m llamaindex_retrieval.cli index-source-revisions \
  --version '完整物理索引版本名' \
  --file-id '文件ID'
```

返回该版本内文件的切片数量、来源版本列表及 `untracked_chunks`。旧数据没有来源记录时明确计为未追踪，不补造历史。查询仅接受当前或有活动资格记录的历史索引，不把失败的暂存索引当成已发布来源。

查询展示的是索引中记录的哈希与地址，不重新读磁盘验证文件，因此明确返回 `snapshot_integrity_checked=false`。准备入库时执行了完整性检查；后续长期归档仍需独立校验与备份。

## 存储与边界

快照位于 `upload_dir/.revisions/<知识库ID哈希>/<文件ID哈希>/<原文SHA>/`，目录内保留原文件名与 `parsed-<SHA>.json`。知识库和文件 ID 经过哈希后作为目录名，不能通过路径片段逃出快照目录。

- 本批覆盖管理员上传文件（Markdown、文本 PDF、DOCX）的入库/重建链路，尚未将 FineWiki 和所有 CLI 导入统一纳入快照机制。
- 本批不是文档编辑或新版本上传界面；尚无正式修订 API。已有文件不能靠直接改写路径来更新。
- 快照独立于原上传目录；删除原文件或知识库不会自动清除历史快照。删除活动检索内容不等于永久擦除历史数据。归档保留、磁盘配额、彻底删除及备份策略尚待实现。
- MongoDB 与 OpenSearch 仍非分布式事务。若发布成功后数据库写入失败，任务可能报错；索引映射中的来源与任务绑定保留，可用于核对。尚无自动跨库修复功能。
- 解析仍沿用现有解析器行为。原始文件字节完整保留，不代表解析器保留了 PDF 排版或完成 OCR。
- 快照位置目前是本地文件 URI，多实例必须共享上传/快照存储。没有将本批称为完整商用文档版本系统。
