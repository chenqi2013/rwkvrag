# 本仓库独立联网与 Tavily 单 Key 验证（2026-09-23）

## 已实现和已配置

- 运行时联网仅接受 `tavily` 或 `searxng`；`WebSearchAdapter` 在本仓库内调用提供方。旧项目子进程不再是运行选项。`SearchReaderAdapter` 名称仅作为冻结历史启动器的兼容别名，历史桥接文件不在当前调用路径，也没有修改冻结实验输入、PINS 或原始结果。
- 自动路由使用本仓库的 HTTP 客户端，配置名为 `web_router_*`，只依赖已配置的模型服务端点。模型选择本身不等于检索或回答质量通过。
- Tavily 只读取一个私有 Key 来源；环境变量和文件不能同时使用，逗号列表、JSON 数组和多行文件会在发请求前拒绝。没有 Key 轮换或故障后尝试下一把 Key。HTTP 401/402/403/432/433 的默认共享冷却为一天，429 依有界 `Retry-After` 或默认 60 秒冷却。
- 本机 18440 已切为 `tavily`，只把用户提供的第一把新 Key 写入被 Git 忽略的 `0600` 私有文件。其余九把没有调用、存储或检查额度。跨进程 SQLite 守卫、单并发和 2 秒最小请求间隔已配置。旧 settings 已私有备份；API 重启后 `/health` 与 `/v1/admin/health` 均返回 200/ok。

## 验证与限制

后端相关 143 项测试通过，修改文件 Ruff 检查通过。当前独立联网检索已能直接使用，完整 RAG 回答仍有来源优先级、Planner 查询覆盖、Writer 复读和引用问题；不能据此宣称商用质量通过。历史 SearchReader 多 Key 失败切换确有放大请求风险，但现有证据不能证明它就是此前账号停用的原因。下一轮质量验证应在同一真实题集上分别看检索官方来源、正文覆盖和最终引用，而不是再批量试 Key。
