# 检索专用 StateTune：来源采集与教师试点

日期：2026-09-23。按[新实验登记](../../EXPERIMENTS.md)准备检索规划数据；**尚无准入训练集、优化器更新或检索质量收益**。原发布V1训练、旧题与原始回归均保持不变。

## 新来源快照

先按20个 GitHub topic 分区，再从各 topic 采集6个许可元数据为 MIT、Apache-2.0、BSD、ISC 或 MPL-2.0 的新仓库 README。获得[120份来源清单](../../../llamaindex-retrieval/statetune/retrieval-v1-20260923/SOURCES.json)：训练84、开发18、留出18，原文字节合计1,544,329。逐份核对 SHA-256 和 Git blob SHA-1、UTF-8 解码、仓库唯一性、已见官方 README 精确哈希及仓库身份，均通过。两次同一候选 README 因长度/身份条件拒绝；拒绝项保留在清单中，不进入120份。原文保留在本机忽略目录 `data/corpora/retrieval-state-v1-20260923/readmes/`，清单给出可按 blob SHA 重新取得的地址。

已见禁入表含65道联网题、434道恢复题、24道新固定材料题去重后的522个精确问题指纹，以及先前真实工程 README 的仓库与字节哈希。它仍不能识别镜像、别名或语义近似；人工来源审读仍必要。当前训练分区只有84个来源族，低于[预登记的120族门槛](../../../llamaindex-retrieval/statetune/retrieval-v1-20260923/MINIMUMS.json)，因此不能直接发布训练集。[345组冻结来源组合](../../../llamaindex-retrieval/statetune/retrieval-v1-20260923/JOBS-v2.jsonl)只是生成任务，不能算345条训练样本。

## 12组同来源教师试点

使用本机私有 DeepSeek Flash 配置，在同12个备份主题任务上试三版提示，每版最多96条输出；每次请求/原文/耗费收据保留于本机忽略目录 `data/quality-runs/retrieval-state-plan-drafts-20260923/`。[试点计数与原始文件哈希](../../../artifacts/retrieval-state-data-20260923/PILOT-SUMMARY.json)可复核。累计保守计费约0.0682美元，未调用训练 GPU。提示、任务清单和原始响应均按版本保存；V1/V2/V3 只是草稿试验，教师未获旧题答案。

| 版本 | 当版结构通过 | 同一严格覆盖规则重审 | 主要失败 |
| --- | ---: | ---: | --- |
| V1 | 20/96 | 未同协议重审 | 枚举和字段写错、类型混用 |
| V2 | 88/96 | 57/96 | 多项目题漏指定项目，只有1条 listed 候选 |
| V3 | 51/96 | 51/96 | 严格要求全部项目与 grid/listed 后，多项仍漏项；listed 0条 |

V3 严格通过的51条中，普通16、比较8、选择1、历史2、缺口12、冲突12；33条只涉及1个对象，6条2个、11条3个、1条4个。51条的问题文字均包含规划中的完整仓库名，但这只查字面提及，不验证所问维度、条件或计划语义。V2 的57/96是用 V3 **同一严格校验器**对原 V2 raw response 事后重算，不能与 V2 的宽松 88/96混成收益。V1 与后两版输出协议不同，不作精确成对效果结论。所有通过者 `review.accepted=false`，不得进入训练。

## 数据方向调整

当前让教师同时发明问题与完整标签，容易生成格式合法但范围不一致的样本。下一版改为：先从来源族与需求结构确定对象、维度、grid/listed 和每对象一次初轮搜索的**标签草案**，再让教师把它写成自然用户问题；模型复核问题是否表达了全部标签，代码验证字段、哈希、项目字面覆盖和跨分区污染，高风险题独立人工复核。不能靠代码偷偷补全教师遗漏的对象；任何修正必须作为新版本记录。普通、3×3、4×4、listed、历史撤回和缺口场景须分别达到数量与质量门槛，之后才生成足量候选并决定是否启动 StateTune。

运行链路尚未接入[实验规划协议](../../../llamaindex-retrieval/src/llamaindex_retrieval/retrieval_plan.py)。因此也不能先训练一个与正式服务提示不一致的 State，再声称改善真实检索。训练前仍需新盲集、精确 prompt/token 绑定、来源族扩充至门槛，以及固定材料/真实检索两层基线。
