## 拟定数据契约

### SourceRevision 与 EvidenceSpan

保留已有不可变来源快照、文件版本和索引发布机制。EvidenceSpan 绑定 source revision、解析器版本、原文起止位置与文本哈希；表格值同时绑定表头、行标题、单位等必要父级上下文。跨度校验是程序职责，语义充分性需单独评测。

### AtomicClaim

原子表示“该来源提出的主张”，不是自动认定的事实。

字段：claim_id、source_revision_id、evidence_spans、对象、属性、值、单位、否定、版本、时间、适用条件、来源声明状态、提取 trace、模型及协议版本。

- 一份来源独立处理，允许没有相关主张；不能因另一份来源存在不同数值而改写本来源。
- 必须同时保存模型原始输出和经结构校验的记录，不覆盖原输出。
- 未知字段保留未知；不能靠对象同名或相同属性直接断言同范围。
- 原文相关但提取失败，与原文没有证据是不同状态。

### EvidenceMolecule 与 ClaimRelation

分子围绕一个明确问题组织一组主张，逐项判断其关系。实体对齐、范围对齐与关系判定均保存证据及模型 trace。

关系候选：support、same_scope_conflict、different_scope、incomparable、explicitly_supersedes、alignment_unknown。缺证据是问题覆盖状态，不应抹去已找到的相关来源。

关系判定需要拆开：先确认是不是同一对象与属性，再检查条件/时间范围，再处理显式修订，最后比较主张是否相容。不能继续将“supported/missing/conflict/scope_difference”当作一个同时表示覆盖程度和关系类别的总开关。每个判断都允许 unknown，并保留其依据。

- 不按摄取时间、资料排列顺序、转载数量或模型自信程度裁定冲突。
- 对显式修订保留被替代原子及修订依据。
- 同范围冲突可以结束为 unresolved；不要求模型一直推理到选出一个值。
- 不进行所有原子的无界两两比较。先找相关候选组，再按当前问题所需属性和范围验证关系。

### ConclusionCard 与 SummaryNode

单项结论卡绑定所回答的问题、有效范围、支持及反对主张、缺口、关系、依赖版本和生成 trace。

逐级组织为：属性结论 → 对象/版本小结 → 跨对象比较或主题 Wiki。每次仅处理有上限的子项目；上层不能提高下层结论的确定性。

前端可以直接渲染已经保存的结论卡与证据边，并为每条边展示真实来源标题、版本和逐字位置。文档内的编号只是来源文本，不参与生成引用身份。自然语言中的引用错误仍作为该输出的问题记录，不能由代码修改原始回答来掩盖错误。

最终呈现优先直接显示结论卡和结构化对比表。自然语言 Writer 只处理当前小节相关结论及其必要逐字证据，不能再次输入整份文档和全部冲突历史。具体规则需遵守 `ARCHITECTURE_RULES.md`：Writer 只能看到 Reader/Resolver 选中的逐字证据；摘要不能替代原始来源。

## 有限任务执行

任务状态建议为 pending/running/completed/incomplete/failed/stale，证据状态与执行状态分开。

每个任务保存输入依赖哈希、阶段、模型/State/协议版本、调用预算、原始请求响应和完成原因。复用中间结果前核对全部依赖版本。

- 提取、对齐、关系判断、单项总结各自有输入和输出预算。
- 格式错误、截断、引文不匹配均保留为失败，不用程序修正文案。
- 相同任务和相同证据不无变化地重试；缺口检索必须指定缺少的对象、属性或范围信息。
- 检索达到预算时保留 unresolved/missing 并终止。重复生成监测是执行保护，不能裁定事实。
- 复核记录具体主张及不支持的证据位置；二元 NO 不能直接触发整篇重写。

## 增量维护和 Wiki

新来源版本进入后，创建新原子记录，通过反向依赖标记受影响分子、结论卡和 Wiki 版本过期。在新快照校验完成前，保留旧的完整快照并展示过期状态。发布以一致快照为单位，避免新原子配旧总结。

来源撤回、删除和权限变化都必须沿依赖传播；派生知识继承来源的知识库和授权范围。不能跨权限复用分子或摘要。

首期沿用现有 MongoDB 与 OpenSearch 保存记录、关系和检索索引；无需先引入图数据库。模型、State、提示协议升级也属于派生结果的版本维度，不能只按原文哈希复用旧结果。
