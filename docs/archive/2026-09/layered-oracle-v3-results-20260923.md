# 逐硬条件 Oracle V3（2026-09-23）

V2把每个项目独立判断后仍只有6/15正确，但输入里保留了两个硬条件与GPU偏好。V3沿用同四组**已见**虚构项目和人工核准事实，每次仅给一个项目、一个硬条件及其对应字段；Windows与许可证各15项。原v10的条件节点也是逐硬条件判断，但V3输入、提示词和Gold材料不是生产节点逐字回放。

诊断性投影规则只在评分脚本里使用：任一条件`not_satisfied`判排除，两项均`satisfied`判合格，其余判待确认；这不是新的生产决策器，也不能替代模型负责语义判断的架构规则。相比V2逐项目判断两组均6/15，这一粒度**在已见Gold事实材料上**减少了错误。训练State仍错5个条件：把赤桁未检查Windows输出为协议外`not_checked`，把岚阙同版Windows矛盾判为不满足，把沐桥 Core 的Windows和许可证两项错判，并把穆桥 Core未检查Windows判为不满足。按项目投影后仍错3/15，正式推荐不能接受。

结论：按单硬条件拆层是值得继续验证的架构方向，训练State在这组短材料上优于零State；**不据此切正式模型或宣称比较题修好**。V1/V2已证明事实抽取、最终Writer和引用仍失败，真实联网与普通题回归也没有本轮验收。下一步应在新真实项目来源上分别测原子事实、单条件与最终Writer，并保留原普通题的成对结果；不能把这些已见虚构材料直接加入训练数据。
