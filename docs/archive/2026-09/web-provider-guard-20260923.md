# 内置网络提供方请求保护与本机切换（2026-09-23）

## 修复范围

- 本机 18440 原配置仍使用 SearchReader 子进程与 8 把旧 Tavily Key。旧提供方在一个查询内遇到 401/402/403/429/432 会立即换下一把 Key，子进程结束后失效记录不保留；[先前诊断](tavily-diagnosis-20260921.md)已用模拟请求证明放大风险。本次不修改 SearchReader 仓库，而把本机服务切到 rwkvrag 内置 Tavily 适配器，只配置单把 Key，并移除服务配置对 SearchReader 项目目录的依赖。软件默认提供方也改为内置 Tavily，旧 SearchReader 路径须显式选择。自动联网的 RWKV 选择器地址和模型仍沿用原配置。
- 内置适配器新增共用 SQLite 请求保护：同一提供方与凭据哈希跨 API 进程串行，完成后至少间隔默认 1 秒；401/402/403/432/433 默认冷却 15 分钟，429 使用有界 `Retry-After` 或 60 秒默认值；5xx 短暂冷却。不会立即轮换或重试 Key。数据库只保存 SHA-256 身份、时间和 HTTP 状态，不保存 Key 或提供方正文。未配置 SQLite 路径的开发运行只在单个适配器实例内保护，多 worker 必须共用路径。
- Tavily 可通过权限 `0600` 的私有 Key 文件读取；明文不写进本机 `settings.json`。文件与 JSON 位于被 Git 忽略的 `data/services/local-app/`，配置 JSON 的权限也收紧到 `0600`。更新前的设置另存为本机私有备份。
- 前端对安全的 `web_upstream_circuit_open_401` 等代码显示 HTTP 状态与“提供方请求已暂缓”，不展示上游正文或改写模型回答。UI 发布到新不可变目录 v6，未覆盖 v5。
