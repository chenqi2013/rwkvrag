# Typed 漏斗修复与失败定位（2026-09-21）

## 结论与范围

用户要求修复大型多项目比较，同时保住普通问答。本轮维持7.2B FP16、零State、本地优化推理引擎、top-1/seed11；没有训练、没有重新联网、没有切换正式18440。真实问题使用此前联网获得的固定材料快照，不能称本轮实时联网效果。

已见13条原子节点的值/类型/单位/缺失一致性从旧协议仅未知项正确，改到13/13；不等于独立留出成绩、范围语义准确率或完整问答准确率。完整v8仍失败，随后完成预算、依赖元数据、引文绑定和末层呈现的工程修复，并冻结v10完整回归。各版本失败原文保持不变。

## 一、已实现的工程修复

- 明确布尔/数量/文本值，使用单个可空value表达“已知/缺失”，避免额外known标签把false和0错误抹掉。数量通过独立短调用保留完整计数或计量单位，不在代码里换算或补单位。
- 原子任务开始前预留Cell、硬条件、资格、关系、决策和Writer调用；按对象/字段轮转分配原子预算。未检查的任务完整记录，不把它们当已验证未知。
- 固定输入依赖由编排器登记，标为`dependency_origin=orchestrator_input`，不再让模型复写每个已知ID。原始模型输出与派生审计分开。
- 新引文契约以模型选中的逐字quote为主，辅助unit ID保留原值并审计。只允许在实际提供文本中精确定位；重复引文须有唯一定位依据，未见文字和跨源文字拒绝。之后仍需独立模型核验，不把字面存在当语义正确。
- 最终Writer接收紧凑的同维度结论、候选资格、决定及逐字证据；不再重复携带完整字段图。普通事实题不带选型图。
- Task解析失败时允许一次独立、可追踪的Writer调用，带精确token装箱；保留失败和原文，不由程序拼接答案。没有证据时独立提示不提供虚构的引用编号示例。

应用配置可选`typed_funnel_v10`，默认仍`single`。候选实现与正式运行服务必须区分。

## 四、任务理解诊断：格式改善不等于语义解决
