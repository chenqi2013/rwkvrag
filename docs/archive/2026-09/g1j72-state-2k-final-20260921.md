# 7.2B 2K StateTune：完成结果与暂停交接

## 结论与范围

截至2026-09-21 00:43（Asia/Shanghai），本轮训练、1600次单条件对照、320次完整分层对照及160对最终回答复核全部完成。单条件判断有明确局部收益，但完整链路未显示可靠的整体改善，选择题还有退步。因此不晋级、不部署这版State；已停止本轮临时推理服务，按用户要求完成汇报后暂停。

本轮只在ASSESS使用训练State，Planner、Reader和Writer保持零State；固定模型、问题、历史、材料、提示词和解码配置。160道完整链路题使用固定材料，不等于新增真实检索或前端验收。原有题目和失败均保留。

## 训练与控制变量

- 2000条训练、400开发、400留出，20类合成条件/材料组合。
- 固定两个epoch，4000次样本访问、2000次优化器更新，最终第二epoch为唯一测试检查点。
- FP16冻结7.2B基座、FP32 State；学习率0.001、累积2、seed20260920；仅授权8222 GPU3。
- 用时2453.66秒，峰值reserved 15,571,353,600 bytes；基座权重未变。
- State SHA256：`d7531abc17996bbac51a119914f7efbe0728e96736fc6eedefa42a9408d6d1d5`。
- 原BF16预检前缀不一致，0次更新；独立诊断后创建FP16执行版本，整段/逐步前向16/16一致、最长样本反向有限。旧失败现场保留。
- 解码是top_k=1贪心，temperature=1、top_p=1；没有把温度设置当作本次收益来源。

### 控制变量的实际限制

配置和输入固定并不保证逐token输出完全一致：7对题的Planner在相同提示SHA、实际输入token序列SHA及解码参数、未加载State的条件下，输出仍不同。160对中4对输入超界未调用Planner，149对实际Planner输出相同，7对不同。另有20对Planner相同而Reader提示/输出集合不同。所有原始轨迹保留。原因本轮未定位，不能把每一处最终回答变化都严格归因于ASSESS训练；不临时改引擎后覆盖本轮结果。

两组各800条全部正常返回。训练State与冻结目标文本及证据列表一致782/800，开发/留出均391/400。零State因措辞不同精确一致为0，不能解读为零准确率。

事后粗方向核对：零State422/800，宽松解释“材料支持/不支持”等歧义措辞为452/800；训练State784/800。最小证据集合一致分别440/800、798/800。方向、最小证据集合及已审读断言联合口径为253/800、782/800。

这不是独立真实问答准确率：未知与冲突合并为不确定；短结论通过显式字典映射，260条长/歧义/不一致记录由实现者逐条阅读，其余通过对应合成标签核对。没有独立人工评审，数据模板共享底层技能。

训练组仍有16条方向错误：区间2、质量单位4、时间单位10；另2条证据集合错误。时间换算只有30/40方向正确。存在零State答对而训练后答错的个例。

### 已核实的链路案例

`pilot-compare_modes`：比较标准/省电续航时，T7/T8的Reader只保留甲的来源S1，没有乙的S2。零State说明乙缺失；训练State对只有一方材料的比较直接给出“不满足/满足”。Writer最终却把10小时与12小时、18小时与16小时的两个大小关系都说反。它既体现双侧证据缺失，也体现最终Writer没有可靠保持判断，不能归因于单一模块。

`pilot-choice_seen`：硬条件900克/10小时，乙1000克超重，两组最终仍推荐乙。`pilot-choice_boundary`：甲900克/10小时恰好合格，乙800克/9小时不合格；零State错选乙，训练组把两者都说成800克/9小时并拒绝选择。

`new-comparison-modes-2`中训练组把同一段四项参数重复10遍；`new-mixed-untrusted_note-3`训练组Writer长度退出没有答案。这两类都保留为失败，不能因HTTP正常或数字出现过而算通过。

## 做好的地方

- 2K数据、实际服务分词、训练契约、数值预检、检查点与原始调用都有可追溯绑定。
- 单条件在合成固定材料上有明确局部收益，能列出失败类型和负向迁移。
- 普通事实、零值、否定、版本/模式区别与部分冲突题保留；没有为比较题删掉旧题。
- 合并引用的前端点击候选已通过36项检查及4类浏览器回放，但未部署正式服务。
- 比较/选择结构契约候选已实现并通过29项检查，未接入模型路由或前端。

## 仍然较差的地方

- 完整选择任务可能修改阈值或忽视硬条件，推荐不合格候选；抄对数值也可能说反大小。
- Planner会引入无关条件或把内部规则规划成子任务；Writer可能自相矛盾、暴露内部任务、超长无答案。
- 引用缺失、内部E编号替代用户来源、错误归属仍需解决；前端显示修复不能修正证据语义。
- 训练数据全部非空、任务ID均T1、证据编号仅E1至E5；真实链路有空证据和更多编号。已观察到空证据时返回E1。这是覆盖缺口证据，不声称已经证明全部错误因果。
- 固定材料候选最多接收4份、每份1800字符的来源；超界题保留为unsupported_input。这不是长文档处理已经完成，后续仍需检索/切块链路承接。
- Reader旧1184唯一输入回归召回77.53%，未通过门槛；本轮State没有训练Reader，不能宣称检索召回改善。
- 固定材料测试不覆盖外部联网质量、真实检索延迟、前端端到端商业验收；自动Wiki仍是草稿能力。

## 以后恢复时的优先级（本轮不执行）

1. 比较题按对象×字段保留两侧原子证据，缺一侧明确未知；硬条件逐候选完成后才进入偏好排序，不能让Writer把排除项加回。
2. 补齐空证据、动态证据ID、多任务ID及事实抽取/相对比较等真实ASSESS输入；保留原有普通题作为固定回归，先做小规模覆盖验证再扩大训练。
3. Writer只消费可追溯判断与来源绑定，验证引用支持关系、上下文版本和停止行为；仍由模型负责语义，工程只做结构/一致性审计。
4. 对相同输入输出不一致做独立引擎复现；在严格评估State迁移时保留同一上游规划/证据回放，并另测自由整链体验。
5. 达到固定材料与真实检索回归门槛后，再整合前端引用候选并验收正式部署。
