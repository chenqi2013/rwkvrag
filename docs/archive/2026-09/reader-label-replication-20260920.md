# Reader 标签扩大复验：召回改善复现，整体胜出门槛未通过

历史实验记录，2026-09-20。当前任务以 [CURRENT](../../CURRENT.md) 为准。本轮未改正式应用、模型配置或训练 State。

## 结论

在固定 RWKV G1j 7.2B、zero State 和 strict-v1 判断任务的条件下，仅将输出标签 YES/NO 改为 ANSWERABLE/INSUFFICIENT，在这批合成材料上提升了有效证据召回，但产生了新的非法标签输出，并使部分表格判断退步。**预登记的有限改善门槛与原晋级门槛均未通过，不宣布整体可靠性已经提升，不部署候选。**

两轮调用顺序反转后，每组 160 条原始输出完全一致。这证明当前材料和配置下可重复，不证明跨材料、模型或真实业务泛化。

## 设计与可追溯性

- 首次推理前冻结提交：`87380c76`；[预登记、数据和执行脚本](../../../llamaindex-retrieval/eval/reader-label-replication-20260920/README.md)。
- 160 条新合成材料，80 正例、80 负例，80 个最小对照对；20 个模板族，每族四组实体/数值变体。不是 160 种独立语义场景。
- 10 类任务；其中两个模板族使用英文问题/材料，其余主要中文。旧 40＋24 条不混入主结果。
- 标签由编写实验的代理编写并自查，**未经独立复核**；新材料基于已知失败类型设计，不是独立第三方盲测。
- 两组、两轮共 640 次顺序调用。每轮先后组顺序各占一半，第二轮逐题反转。第一轮为主分析，第二轮只查稳定性，不扩大独立样本数。
- 同一 7.2B checkpoint、zero State、完整 prefill、32-token 输出预算、4096-token 输入限额、stop token 0；无重试或输出修补。实际输入 379–437 tokens。
- 请求 temperature=0；客户端传输时下限为 0.001；专用评测服务实际使用 `logits.argmax()`。两组完整传输参数一致。
- 权重 SHA-256 来源于此前已核验部署；健康接口只核对 ready、模型名和 zero State，不能独立证明权重哈希。

审计核对了全部 320 个组间配对只改变指令中的标签，原始数据内容一致；320 个跨轮配对 prompt 一致；冻结文件、原文、prompt 和 raw output 哈希一致。640 次均正常 stop。结束后新增的导出脚本不属于事前冻结的推理或评分代码。

## 主结果：第一轮，160 条

| 指标 | YES/NO | ANSWERABLE/INSUFFICIENT |
| --- | ---: | ---: |
| 正例命中 TP | 63 | 76 |
| 正例漏选 FN | 17 | 4 |
| 负例误选 FP | 0 | 0 |
| 负例正确拒绝 TN | 80 | 76 |
| 无效输出 | 0 | 4（均为负例） |
| 有效证据召回 | 78.75%（63/80） | 95.00%（76/80） |
| 总准确率，含无效输出 | 89.375%（143/160） | 95.00%（152/160） |
| 成对正确率 | 78.75%（63/80） | 90.00%（72/80） |
| 已选择证据的精确率 | 100%（63/63） | 100%（76/76） |

零误选不是零失败：候选的四个非法输出保留在分母中，不能改算正确拒绝。第二轮全部计数相同，两组各 160/160 条原始输出一致。

逐题有 **16 条修复、7 条退步，净增 9 条正确**；总准确率提高 **5.625 个百分点**。按 20 个模板族整体重采样 10,000 次的 95% 百分位区间为 **−5.00 至 +16.25 个百分点**，跨零。该区间只描述本批合成模板的敏感性，不是生产分布上的置信保证。移除任一模板族后最小净提升约 3.29 个百分点。

## 哪些改善，哪些退步

下表正例命中分母每类均为 8；各类另有 8 个负例。

| 类别 | 基线正例命中 | 候选正例命中 | 候选无效输出 |
| --- | ---: | ---: | ---: |
| 否定结论 | 0/8 | 8/8 | 0 |
| 明确肯定 | 8/8 | 8/8 | 0 |
| 零值/未知 | 6/8 | 8/8 | 0 |
| 时间范围 | 7/8 | 8/8 | 0 |
| 地域范围 | 8/8 | 8/8 | 0 |
| 对象区分 | 4/8 | 8/8 | 0 |
| 属性/单位 | 8/8 | 8/8 | 0 |
| 表格 | 6/8 | 4/8 | 0 |
| 修订状态 | 8/8 | 8/8 | 0 |
| 引用指令干扰 | 8/8 | 8/8 | 4 |

否定材料的改进与“证据支持标签可能和事实的肯定/否定含义混淆”这一假设相容，但不能据此证明内部机制。对象、零值等也变化，不能归为单一根因。

四个无效输出全部来自同一旧标签引用模板族的负例，原始输出均为 `{"answer":"NO"}`；候选协议不接受 NO。它们是一个模板族的四个变体，不能说发现四种独立攻击。对称设置的新标签引用模板族未出现错误，也不等于已经通过完整注入防御测试。

四个候选漏选全部是表格正例。其中三个是新增退步，一个原本也错；另外一个表格正例被修复，所以表格净退步两个。不能仅看类别净计数而隐藏个别变化。例如，标题与表头在 contexts、`| 省电 | 48 |` 在 text 中，本应有答案却输出 INSUFFICIENT。结构关联可能是下一项待检验因素，本轮未验证原因。

## 可直接分享的简版

> 我们对 RWKV G1j 7.2B 的证据支持判断做了一次预登记单变量复验：固定模型、zero State、提示主体和输入，只将 YES/NO 改为 ANSWERABLE/INSUFFICIENT。160 条合成材料（20 个模板族，正负各 80 条）上，有效证据召回由 78.75% 升至 95%，总准确率由 89.375% 升至 95%；反转调用顺序重复一轮，逐题输出完全一致。但候选新增 4 个非法标签输出，表格正例命中由 6/8 降至 4/8，按模板族估计的准确率差值区间跨零，因此未通过事先登记的整体改善门槛。结论是：标签措辞能明显改变这个子任务的表现，改善和退步都可重复；目前不能宣称换标签就全面解决了 RAG 质量问题。材料由作者自查，尚无独立标注复核。
