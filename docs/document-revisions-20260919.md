# 知识维护第四批：正式文档修订与失败恢复

日期：2026-09-19。承接 [原文快照与索引来源绑定](source-revisions-20260919.md)。

## 用户现在可以做什么

文档管理页对就绪文件提供“上传新版本”。选择 Markdown、文本 PDF 或 DOCX 后，系统为同一个文件 ID 建立修订任务；保持所属知识库不变。

- 新文件单独保存，不覆盖旧原文；排队、解析和索引构建期间下载入口仍指向旧文件。
- 新索引发布成功后才更新文件名称、原文路径、内容哈希、大小、切片数及最近入库来源。
- 解析失败时旧下载和旧索引保持有效，文件恢复就绪并显示错误，可以重新提交修订。
- 已开始发布但结果不明，或索引已发布而数据库写回失败时，文件保持处理中并显示错误，提供“恢复修订任务”。恢复会用原来保存的新文件重新完成发布和登记，不自动退回旧内容。
- 失败信息存在时不再显示虚假的活动进度动画。

## 接口

`POST /v1/admin/files/{file_id}/revisions`

multipart 字段：`file` 与 `expected_sha256`。后者取自当前文件详情。成功返回 202，包含 `job_id` 和任务状态。

`POST /v1/admin/files/{file_id}/revisions/retry`

恢复当前文件最近一次失败的修订任务。重复恢复、旧操作令牌或非修订任务会被拒绝。

两者沿用现有管理接口的部署和访问控制环境；本批没有补齐应用级资源授权，不应将管理接口公开给不受信任的用户。

## 一致性与并发

- 提交时校验旧哈希和就绪状态；再由 MongoDB 原子条件更新取得文件操作令牌。过期页面、并发修订和已开始的重建/删除不能重复占用同一文件。
- 修订内容先预留哈希，避免索引发布后才遇到数据库的内容重复约束。新增复合唯一索引覆盖知识库与文件历次预留内容哈希；新上传也参与同一约束。
- 本版保守保留预留哈希（包括失败尝试），同知识库其他文件不能再次占用这些内容。尚无预留释放、跨文件合并或历史清理入口。
- 修订草稿与操作令牌在文件记录中一起保存，任务使用稳定 ID。若写入草稿后创建任务失败，服务启动时按草稿补建任务，不覆盖已存在任务。
- 原文、MongoDB 和 OpenSearch 不是单个事务。恢复设计以“保留原始材料、拒绝无条件覆盖、完成同一修订”为原则；不能保证跨存储瞬时一致。
- 任务系统仍未完成多实例租约和完整认领机制。当前应统一升级写入端，并使用单一应用任务调度实例；索引写锁不等于任务调度已支持任意多实例。

首次升级会为已有文件回填 `content_hashes` 并创建唯一索引。部署应先停止旧写入端、备份数据库并验证迁移；本次测试没有对实际业务数据库执行该迁移。

## 验证

真实 MongoDB 与 OpenSearch 联合验证：

1. 新索引成功后才切换下载文件，旧原文和旧索引仍保留。
2. 过期哈希、并发修订、修订期间重建和删除被拒绝。
3. 新文件无法解析时保留旧版本就绪。
4. 发布成功但响应丢失后，可恢复同一修订。
5. 数据库写回失败后可恢复。
6. 草稿已保存而任务创建失败，启动恢复补建任务。
7. 与其他文件内容冲突在发布前拒绝。
8. 实际 multipart HTTP 路径验证必填参数、202 响应，以及发布前后的下载内容。

全部真实测试只使用随机隔离数据库、索引和临时文件。测试日志、前端构建与回归证据见 [验证目录](../artifacts/document-revisions-20260919/)。前端只做了类型检查、构建和既有行为测试，没有声称完成浏览器交互验收。

## 仍未交付

- 尚未部署到业务应用；当前运行服务不会自动获得新接口或按钮。
- 尚无文档历史版本列表、单文档一键回滚或富文本编辑器。
- 删除当前文件会清理其原上传及修订目录，但独立历史快照和旧索引仍保留；页面确认文案已经说明这一点。永久擦除与保留期限策略尚未实现。
- OCR、外部同步、自动 Wiki 与 Agent 补证据循环仍未完成；本批提供了它们依赖的正式文档更新入口。
