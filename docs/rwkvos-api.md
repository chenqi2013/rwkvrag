# 2.9B 外部 API 验证与运行位置

2026-09-08 按用户要求使用 **RWKV7 G1j 2.9B**。优先使用外部 API，不可用时使用本机 RTX 5070 Ti 16GB；不再在 `rwkv-8222` 上运行本任务。此前 13.3B 实验仍是历史记录，不改写为 2.9B 成绩。

## 已验证

- `GET /v1/models` 与成功生成响应都返回 `rwkv7-g1j-2.9b-20260831-ctx16384`。这是服务提供的模型身份，不是远端权重哈希证明。
- `POST https://api-3b.rwkvos.com/v1/batch/completions` 可调用，使用 `contents` 数组、`stream=false`。
- 用户样例的 JSON 末尾多余逗号已在测试前去除；其中过期 `state_id` 导致 400。独立新请求只移除 `state_id` 后为 200，耗时约 1.94 秒。
- 两项合成中文资料问答的批处理返回两个不同 index，均自然完成。`temperature=0` 被拒绝，服务声明最小值 0.001；使用 0.001 后为 200，约 0.85 秒。
- 两项事实均答对，但都遗漏了所要求的引用标签。这只是传输和小样例检查，不是完整 RAG 或引用质量验收。

共有 6 次 HTTP 尝试；保留失效状态、无文档端点及不支持温度的错误，没有自动重试。去掉状态后的样例与两项批处理合计产生 3 个输出。结构化结果及原始收据哈希见 [验证记录](rwkvos-api-probe-20260908.json)。认证值不进入仓库。

## 与现客户端的差异

现客户端使用 `/tokenize` 和 `/v1/completions`，并要求精确 token/BOS/usage 校验及原生文本边界。本次已验证的外部接口使用 `contents[]`、`choices[].message.content` 和 `alpha_*` 参数，响应没有 usage。因此需要独立传输适配，不能只替换 `NATIVE_BASE_URL`，不能补写模型文本或伪造预算验证。未据此断言服务不存在其他兼容端点。

项目原生客户端的默认模型名已改为 2.9B，默认地址仍为本机 loopback，供后续本机部署使用；这不表示本机服务已启动。2.9B 完整 RAG 基线尚未运行，旧 13.3B 的 16/29 事实与 1/8 正式完整分数不适用于本接口。

服务器本任务拥有的服务已停止，模型、数据库和实验文件保留在磁盘。后续外部接口适配、数据库迁移与测试不能重新占用该服务器。
